## 2. 烧录地址证据（非默认推断）

`partitions.csv` 与构建实际分区表二进制一致：

```
ota_0, app, ota_0, 0x10000, 0x1E0000   ← app 分区起始 0x10000，大小 0x1E0000(1920K)
```

- 解析源：`build-release/partition_table/partition-table.bin`
  （SHA-256 `1c70e3068c81a8822da51fa4379a875548844027a9da6cfb1f471570012ad811`）
- BIN 大小 1175632 B = `0x11F050`；写入区间 `[0x10000, 0x12F050)`；`ota_0` = `[0x10000, 0x1F0000)`
  ⇒ **`0x12F050 < 0x1F0000`，写入完全落在 `ota_0` 内**，余量 `0xC0FB0`
- **不执行 `erase-flash`**；`write_flash` 仅擦写 app 分区涉及扇区

## 4. 执行流程（批准后）

1. `preflight_flash.py --port /dev/ttyUSB1 --log-dir <本次> --expect-device-id IotHub-65D8 --bin <冻结BIN> --expect-bin-sha256 047e…ea41 [--elf … --expect-build-sha a7e04b6a9]` → **必须 rc=0**；
2. 停 `/dev/ttyUSB1` 录制，记 gap；
3. `tools/flash_frozen.sh <冻结BIN> 047e…ea41`
   （**仅 2 参数**：端口 `/dev/ttyUSB1`、芯片 `esp32`、地址 `0x10000`、分区上限
   `0x1E0000` 均已锁死在脚本内；脚本把输入复制到私有冻结目录 → 对副本校验
   SHA-256 → 写入前再校验 → `esptool write_flash 0x10000` → **写入后再次校验并强制比对**）；
4. 恢复录制；复位进 app（`esptool run`，本机已证可清除 DOWNLOAD_BOOT 状态）；
5. BLE 反证：`device.info.build_sha == a7e04b6a9`；串口 `app_init: ELF file SHA256: a7e04b6a9`；
6. 重建 65D8 基线（uptime / SSID / mqtt / owner 初始）；
7. 执行 **R1/R2/R3/R5/R6**（矩阵同前；R2 = BLE 断连取消路径）。

## 5. 停止条件

- 门禁 rc≠0 / 冻结 BIN sha 不符 / 写入前复查不符 → **不写 Flash**；
- 写入后 `build_sha` ≠ `a7e04b6a9` → STOP；
- 任一 R 项失败、owner 粘滞、cleanup 无终态、出现假 NONE → STOP；
- 录制链不完整 / 证据缺失 → STOP（不补造）。
