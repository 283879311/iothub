## 3. 执行步骤（批准后）

| # | 动作 | 判据 |

| E1 | 串口采集开启 → `write_flash 0x10000 artifacts/p0_static_reapply/iothub.bin` | `Hash of data verified`；SHA 与 §1 一致 |

| E4 | 串口埋点核对 | `sta_start_evt gen=N` 出现次数 == apply 次数；每次对应 `apply_start_released gen=N`；无 `apply_start_timeout`（若出现走 E5） |

| E6 | 收尾 | 静态 `.50`、MQTT 在线、BLE 可查询；无 abort/Guru/重启循环；记录最终 SHA 与日志 SHA-256 |

## 4. A–G 用例矩阵

| 用例 | 内容 | 可构造性 | 判据 |
| --- | --- | --- | --- |
| A | 身份与持久字段预检 | 可 | 三新字段存在；`persistent_use_static=true`；`persistent_static_ip=.50` |
| B | `network.reconnect` ×3 正常路径 | 可 | 3/3 成功，IP 恒 `.50`，`cfg_state=static` |
| C | 埋点计数一致性 | 可 | `sta_start_evt` 次数 == apply 次数；每次有 `apply_start_released` |
| D | 超时 → 候选重试 | **不可构造**（产品 BIN 无注入） | 自然出现时：`timeout` → `retry_candidate` → `.50`；未出现记 N/A，不判失败 |
| E | 迟到事件门控 | **不可构造** | 若 timeout 后出现迟到 `sta_start_evt gen=N`，该 gen 必须等于已超时代，且不得产生第二个 `apply_start_released gen=N` |
| F | N06 MQTT 全链路回归 | 可 | 与 38/40 基线一致，N06 PASS |
| G | 收尾状态 | 可 | `.50` + MQTT + BLE 广播；无异常复位 |

D/E 的强制构造需要 `APP_WIFI_FAULT_INJECT` hooks 构建，属独立批准项，不在本卡内；本卡只做“自然触发观察”。

## 5. 判定

| 判定 | 条件 |
| --- | --- |
| **PASS** | A/B/C/F/G 全过；E4 无 timeout，或 timeout 时 D/E 观察项满足 |
| **PASS（无超时样本）** | A/B/C/F/G 全过，D/E 记 N/A —— 说明 P0 修复后未再触发该路径；`cfg_state`/重试仍为未验证路径，需在报告中明确写出 |
| **FAIL** | B 出现降级（IP 变 `.28`/DHCP）、`cfg_state` 与实况不符、重复 `retry_candidate`、abort/重启循环、N06 回归失败 |

## 6. 收尾与回退

1. 无论结果，先保日志、`network.status`、`device.info` 回读，逐文件记 SHA-256；
2. 通过则设备保留 P0 候选，作为下一轮 P1 的基线；不通过则回写 `a792158d…` 并复验 `.50`/MQTT；
3. 禁止以“刷固件”代替定位；禁止擦 NVS 或整片 Flash。

## 7. 已知偏差（实现记录需同步）
