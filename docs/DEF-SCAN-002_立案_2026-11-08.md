# DEF-SCAN-002 立案：BLE 活跃时自定义 active scan time 导致扫描饿死（2026-11-08）

## 现象

T4 用例 4（10 次 network.scan）首扫 30s 无回包 → 客户端超时 → 断链级联
（12 项 SKIP）。串口铁证（uptime 4,091,517，mini-program notify 活跃期）：

```
ble_cmd: rx v1 cmd=network.scan id=88
wifi:Error! Should use default active scan time parameter for WiFi scan
      when Bluetooth is enabled!!!!!!
[其后 30s+ 仅 MQTT 心跳——无扫描结果、无回包]
```

## 根因

`main/wifi.c` scan 配置设了**非默认 active scan time（min=50/max=100ms）**。
IDF 驱动在 BLE 开启时明确要求默认参数；共存调度下 50-100ms 的 WiFi 窗口
被 BLE（高优先级）饿死——扫描不完成。BLE 空闲时侥幸完成（历史 5.8s 实测），
BLE 活动 + notify 流量时确定性失败。错误历史存在于 17+ 份归档串口
（长-standing，非 netcheck 期回归）。

## 修复（已上机，commit c1a623fa2 时代）

`scan_time.active.min=0/max=0`——交还驱动默认值（错误信息即修法）。
无 BLE 时行为几乎不变（默认 max 120ms vs 自定义 100ms/信道）。

## 验证

- 修复后 BLE 会话（notify 活跃）+ network.scan ×1：**6.0s 完成、8 AP**（功能证据）；
- #2/#3 busy = DEF-SCAN-001 节流正确工作；
- 驱动错误修复后未再现（串口该时段丢行，以功能结果为准——串口通道在
  BLE notify 期不可靠已两次记录）。
