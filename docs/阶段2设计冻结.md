# 阶段 2 设计冻结决策清单

> 基线：`feature/shared-config-cmd`。
> 依据：`docs/命令与配置依赖清单.md`、`docs/命令与配置源码核验.md`。
> 本文件冻结设计契约，不代表功能已实现或测试通过。本轮不改代码。

## 1. 五项冻结决策

### D1 · 配置事务恢复：恢复旧快照（冻结）

- 提交前保存旧主配置和旧 Wi-Fi profile 快照。
- 主配置或 profile 任一写入失败，都进入恢复流程。
- 恢复完成后，正式配置与 profile 必须回到一致的旧状态。
- 恢复失败必须报告独立的恢复错误，不能伪报事务回滚成功。

设计边界：

- NVS 的 `iothub/runtime_cfg` 与 `iothub/wifi_profiles` 是两个独立键，不具备天然原子性（`config.c:15-17`）。
- 旧快照恢复是运行时事务策略，不等于断电原子性；断电一致性另行设计。
- 当前 `config_apply_patch()` 是“先写 NVS、再应用域”（`config_apply.c:864`），实现 D1 时不能把它误当成已有事务。

### D2 · 候选识别：候选代次 + SSID（冻结）

- 每次试连分配新的候选代次或唯一 `trial_id`。
- 记录候选 SSID、状态、开始时间和超时。
- Wi-Fi 事件必须绑定当前候选代次；旧事件、候选过期事件不得触发成功或提交。
- SSID 只用于辅助核对，不能单独作为事件归属依据。

现状差距：

- 当前 `app_wifi_try_connect()` 在 `WIFI_EVENT_STA_CONNECTED` 就置成功（`wifi.c:1085-1094`），不是 IP 条件。
- 试连期间的 `IP_EVENT_STA_GOT_IP` 直接返回（`wifi.c:1234-1241`），没有记录候选 IP。
- 试连只依赖两个全局 bool（`wifi.c:45-50`），没有候选代次或 SSID 绑定。

### D3 · 异步操作结果：`operation_id` + 查询 + BLE 通知（冻结）

- 耗时操作先返回受理结果，再异步完成。
- 通过 `operation_id` 查询状态和最终结果。
- BLE 通知用于主动告知；查询接口用于补偿丢失通知。
- 同一操作的重复查询不得重复执行操作。
- 重复提交的去重规则必须在命令契约中明确（`idempotency_key` 与 `operation_id` 分离）。

现状差距：命令层没有 `operation_id`，也没有 `operation.get`；BLE/MQTT/HTTP 都只返回同步结果。

### D4 · UART 配置：接入 `config_apply`，保留硬件回滚（冻结）

- UART 配置接入统一配置应用路径。
- 保留 `uart.c` 现有的硬件应用与失败恢复能力。
- 顺序固定为：**校验 → 应用硬件 → 持久化 → 保存失败则回滚硬件**；硬件应用失败不进入持久化。
- 不能出现命令层宣称成功、UART 驱动实际未生效。

现状差距：

- UART 字段已登记，但 `config_apply_domain_wired()` 没有 UART 分支（`config_apply.c:688-700`），`config.set` 提交 UART 会被拒绝。
- 现有 HTTP UART handler 已实现“应用硬件 → 保存 → 失败回滚”（`uart.c:539-580`），可作为统一路径的硬件钩子参考。

### D5 · BLE 安全：单独安排（冻结）

- BLE 链路安全独立规划、独立验收，不与网络候选状态机混为一体。
- 当前 `login` token、600s TTL、断线失效、5 次/秒限频作为现状保留。
- 在链路加密、配对/绑定完成前，不把 `SM_LVL=0` 视为具备链路安全保障。
- 高权限操作的授权边界仍需明确；BLE 安全独立不代表可以忽略命令权限修正。

现状事实：`ble_cmd.c:24-26`、`ble_cmd.c:198-207`、`ble_cmd.c:240-260`；NimBLE `SM_LVL=0`。

## 2. 异步配网状态机（冻结）

状态集合：

```text
IDLE
CONNECTING
GOT_IP
COMMITTING
SUCCESS
FAILED
CANCELLED
```

恢复失败作为 `FAILED`/`CANCELLED` 的附加结果记录，不视为成功恢复。

| 当前状态 | 事件/命令 | 约束 |
| --- | --- | --- |
| `IDLE` | `network.tryconnect` | 创建候选操作并返回 `operation_id` |
| `CONNECTING` | 候选关联且获得 IP | 校验候选代次，进入 `GOT_IP` |
| `CONNECTING` | 错误密码/AP 不存在/超时 | 进入 `FAILED`，执行恢复 |
| `CONNECTING` / `GOT_IP` | `network.cancel` | 停止候选并恢复旧网络 |
| `GOT_IP` | `network.apply` | 校验 `trial_id` 后进入 `COMMITTING` |
| `COMMITTING` | 两项持久化均成功 | 进入 `SUCCESS` |
| `COMMITTING` | 任一持久化失败 | 恢复旧快照，记录原始错误与恢复结果 |
| `COMMITTING` | `network.cancel` | 不承诺撤销已完成的 NVS 写入；返回提交中状态 |
| 任意终态 | `operation.get` | 返回已保存的最终结果，不重新执行 |

冻结规则：

- 同一时间只允许一个活动网络候选；新试连不得静默覆盖旧操作。
- `GOT_IP` 只表示候选获得 IP，不表示正式配置已提交。
- 取消、超时和 IP 同时发生时，用状态检查和候选代次保证只发生一次有效转换。
- `SUCCESS` 只表示配置提交成功，不保证 MQTT 已恢复连接。
- 终态结果保留一段明确生命周期，避免 BLE 短暂断连后无法查询。

## 3. 跨模块职责边界（冻结）

| 模块 | 职责 | 禁止行为 |
| --- | --- | --- |
| `ble_cmd.c` | 解析、授权、投递、返回受理结果 | 阻塞等待 Wi-Fi 连接 |
| `cmd.c` | 分发、来源权限、统一响应 | 因入口统一而放宽 MQTT 权限 |
| `wifi.c` | 候选操作、事件归属、超时、取消、网络恢复 | 仅凭 `STA_CONNECTED` 判定成功 |
| `config_apply.c` | 校验、域应用协调、持久化边界 | 保存/应用失败时伪报成功 |
| `config.c` | 主配置版本与保存接口 | 假定两个 NVS 键天然原子 |
| Wi-Fi profile 管理 | profile 读写与恢复 | 主配置成功后忽略 profile 失败 |
| `mqtt.c` | 正式网络可用后的连接与状态上报 | 把候选 IP 当成正式网络切换 |
| `uart.c` | UART 硬件应用与失败回滚 | 统一路径绕过硬件回滚 |
| HTTP handlers | 兼容端点，逐步复用共同语义 | BLE 等价能力未验证就删旧端点 |

## 4. 目标权限矩阵（冻结，非现状）

| 命令/能力 | HTTP | BLE | MQTT RPC |
| --- | --- | --- | --- |
| 读取脱敏配置、设备状态 | 允许 | 允许（登录后） | 允许（按字段脱敏） |
| GPIO / LED / 继电器控制 | 允许 | 允许（登录后） | 允许（按策略限制） |
| Wi-Fi 扫描 | 允许 | 允许（登录后） | 禁止 |
| Wi-Fi 试连、取消、提交、重连 | 允许 | 允许（登录后） | 禁止 |
| MQTT host/token 配置 | 允许 | 允许（登录后） | 禁止 |
| UART 配置 | 允许 | 允许（登录后） | 禁止修改 |
| `uart.send` | 允许 | 允许（登录后） | 默认禁止 |
| `data.loopback` | 允许 | 允许（登录后） | 禁止 |
| 蓝牙角色/名称配置 | 允许 | 允许（登录后，按策略） | 禁止 |
| 管理员凭据、配网 PIN | 按现有管理员验证 | 按授权策略 | 禁止 |
| 重启、恢复出厂 | 受保护 | 受保护 | 默认禁止 |

权限实施必须在共享命令核心或统一授权层，不能只靠隐藏 Web 按钮或限制 BLE 客户端。HTTP 与 BLE 的认证机制不同，不能把“已登录”直接等同为同等级链路安全。

现状差异（详见源码核验）：

- MQTT 仍可执行 `uart.send`、`data.loopback`、修改 BT/GPIO/datapipe（`cmd.c:37-59`）。
- `config.set` 的 MQTT guard 只覆盖 net/MQTT 域。
- `web.auth.set` 保存后不主动作废旧 Web 会话。

## 5. 验收条件（冻结）

### A. 网络正确性

- 错误密码不会进入 `GOT_IP` 或 `SUCCESS`。
- 目标 AP 不存在返回明确失败原因。
- 只有候选关联且获得 IP 后才允许提交。
- 旧连接事件或过期候选事件不能提交配置。
- 试连超时后恢复旧配置与网络状态。
- 取消与获得 IP 竞态只产生一个有效结果。
- 主配置成功、profile 失败时恢复旧快照。
- 恢复自身失败返回独立恢复错误。

### B. BLE 与操作结果

- BLE CMD 回调不等待 Wi-Fi 试连完成。
- 长时间试连期间 BLE 控制与数据通道仍可用。
- 每个异步操作可通过 `operation_id` 查询。
- BLE 通知丢失后仍可查询最终结果。
- 超长命令和响应分片失败返回明确错误。
- 重复查询不会重复执行命令。

### C. 配置与权限

- UART `config.set` 成功后硬件参数确实生效。
- UART 应用失败时硬件与配置按策略恢复。
- MQTT 无法调用禁止的网络、UART、loopback、BT 修改命令。
- 配置提交成功与 MQTT 恢复连接分别报告。
- Web 旧端点在迁移验收前继续可用。

### D. 资源与稳定性

- 记录试连前、试连中最低值及结束后的 free heap。
- 记录 largest free block 最低值。
- 确认试连与恢复不持续泄漏内存。
- 确认超时、取消、重复请求不会积累任务或队列。

## 6. 尚未冻结的实现细节

1. **断电一致性**：两次 NVS 写入之间断电的事务标记/启动恢复机制。
2. **候选硬件行为**：试连是否必须拆旧 STA、如何恢复驱动配置、事件订阅与重连时序，需按当前 `wifi.c` 再次核对。
3. **操作结果保留**：保留多少条、多久过期、重启后是否保留。
4. **错误码**：`wrong_password`、`ap_not_found`、`timeout`、`nvs_commit_failed`、`rollback_failed` 的统一枚举及底层可区分性。
5. **BLE 安全专项**：链路加密、配对/绑定、凭据变更后的会话失效、高权限授权。

## 7. 实施顺序（冻结）

1. 按冻结矩阵修命令权限、BLE 超长/分片错误响应。
2. 设计并验证主配置/profile 旧快照恢复。
3. 定义 `operation_id`、候选代次、状态转换的数据结构和接口。
4. 再修改 `wifi.c`、`mqtt.c`，实现候选状态机与 MQTT 事件隔离。
5. UART 配置统一接入，单独回归硬件应用与回滚。
6. BLE 链路安全专项独立推进。
7. Web 清理和 ThingsBoard OTA 继续排在后面。
