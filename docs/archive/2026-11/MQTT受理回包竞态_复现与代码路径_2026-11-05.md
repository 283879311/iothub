# MQTT 受理回包竞态（孤儿 trial）— 复现条件与代码路径

> 立项编号建议 **DEF-MQTT-001**；本文只做复现/路径取证，不含代码改动。
> 现成证据：`artifacts/p1_state_probe/`（P1 验收 r1/r2 失败现场）。

## 1. 一句话

MQTT 源的 `network.tryconnect` 在**受理回包尚未被 broker ACK** 时就开始 WiFi 试验重启，TCP 链路被拆导致回包丢失；发起端（runner/小程序）收不到 `accepted` 就不会发 `network.apply`，操作槽被孤儿 trial 占住直到 `got_ip_ttl=300s`，期间所有命令返回 `busy`，设备停在 trial 的 DHCP 地址（实测 `.28`）。

## 2. 复现条件

- 源 = MQTT；设备处于静态 IP（trial 走 DHCP，失败即 `.28`）；目标 AP 可达（不可达会先走 scan，时序不同）。
- 窗口：`app_operation_create()` 返回后约 **20ms** 内开始 WiFi stop/start。
- 放大因素：MQTT outbox 积压（现场 `outbox=122 → 599`），发布排队加剧丢失。
- 复现率：P1 验收 **1/1**（r1 命中）；设备重启清槽后 40 例全通过，说明只在"积压 + 紧邻重启"时触发。

## 4. 代码路径

| 位置 | 作用 |
| --- | --- |
| `main/mqtt.c:670-690` | `app_mqtt_publish_command_response()` → `esp_mqtt_client_publish(client, topic, body, 0, /*qos*/1, 0)`；**返回值 msg_id 被丢弃**，无 ACK 等待 |
| `main/cmd.c:386` | `app_cmd_net_tryconnect_async()` 建 operation（owner=MQTT） |
| `main/operation.c:312` | `app_mqtt_defer_restart_begin()`（上限 `APP_MQTT_RESTART_DEFER_MAX_MS=15000`，`main/mqtt.c:1018`） |
| `main/operation.c:21` | `APP_OPERATION_DEFAULT_GOT_IP_TTL_MS = 300000`（5 分钟） |
| `main/cmd.c:347` | `async tryconnect ssid=... op=...` 之后 worker 立即进入 trial 的 WiFi 重启 |
| `main/operation.c:322-336` | 单活动槽：已有活动操作 → `ESP_ERR_INVALID_STATE` → 上层映射 `busy` |

## 5. 修复方向（与你的方案一致）

1. **主修复**：`app_mqtt_publish_command_response()` 返回 msg_id；新增 `app_mqtt_wait_published(msg_id, timeout_ms)`（事件位 + `MQTT_EVENT_PUBLISHED` 比对 msg_id），MQTT 源网络事务受理回包**有界等待 500–1000ms** 后再放行 trial；超时**不阻塞**，记 `resp_ack_timeout`。
2. **安全网**：trial TTL 300s → **60–120s**；到期转 `failed` + 新错误码 `trial_expired`，cleanup 走 `cfg_txn_guard_exit` 并恢复持久配置（静态 `.50`）。
3. **可观测**：`network.status.trial` 增 `deadline_remaining_ms`；接收理回包 ACK 耗时日志（`resp acked msg_id=… t=…ms`）。

## 6. 验收判据（5 条）

1. 正常：MQTT tryconnect 收到 `accepted`，串口出现 `resp acked msg_id=… t=<1000ms`。
2. 故障注入（broker 在受理瞬间断开）：设备 1s 内仍进入 trial，日志 `resp_ack_timeout`，不阻塞、不崩。
3. 孤儿：注入断连且不发 apply → 60–120s 内 `trial_expired`，槽位释放，`config.set` 立即可用（不再 `busy`）。
4. 配置恢复：过期后 `sta_ip=.50`、`cfg_state=static`，不残留 DHCP `.28`。
5. 回归：41 例全绿（含 T01b），N06a/b/c `success`。

## 7. 风险与契约影响

- 500–1000ms 等待只作用于 **MQTT 源网络事务的受理回包**，不影响查询类命令；
- TTL 从 300s 缩到 60–120s 属 G3 操作契约变更，需确认客户端轮询窗口（N06b 轮询为秒级，余量足够）；
- 不改 v1 envelope/错误码语义，仅新增 `trial_expired` 与两个诊断字段。
