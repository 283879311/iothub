> 触发：T4 自检第 17 项 —— `firmware=1.2-a35eef9-dirty（无 git 短 SHA…构建标识无区分度）`。
> 事实核对：今天所有镜像（a792 / b24b0a95 / dc29aa86 / 84b0329b / 51e56693）在 `device.info` 里
> **都是同一串** `1.2-a35eef9-dirty`——工作区未提交，`git describe` 只看到 `-dirty`，差异不进标识。
> 状态：**已实现、构建通过；待只读核验后烧写。**

## 1. 改动

### 1.1 版本号 1.2 → 1.3（`CMakeLists.txt`）

- `PROJECT_VER = 1.3-<git短SHA>[-dirty]`，把 v1-only + 本轮全部修复（静态 P0/P1、MQTT 001/002/003、BLE-001、SCAN-001）与 1.2 时代分开。
- `esp_app_desc.version` 上限 32 字符，`1.3-a35eef9-dirty` 17 字符，安全。
- 全仓无代码消费该串做逻辑判断（仅 `device.info.firmware` 与 MQTT `fw_version` 遥测），纯展示。

### 1.2 `device.info` 增加法字段 `build_sha`（`main/cmd.c`）

```c
const char *elf_sha = esp_app_get_elf_sha256_str();   /* app descriptor 内嵌的 ELF SHA-256 */
if (elf_sha && strlen(elf_sha) >= 16) {
    char build_sha[17];
    memcpy(build_sha, elf_sha, 16); build_sha[16] = '\0';
    cJSON_AddStringToObject(root, "build_sha", build_sha);
}
```

- 取 ELF SHA-256 **前 16 hex**：与二进制一一对应，脏树也能区分；
- 纯加法字段，旧客户端忽略；
- 不复用 `firmware`（保留 `-dirty` 语义），两个字段各司其职。
