## 1. 目标与范围

裁决）：

| 分支 | 构造方案 | 预期 wire |

| 04a expired（got_ip 300s TTL） | MQTT async tryconnect(CMCC-502+口令) → got_ip → **不 apply** → 静置 ≥300s（got_ip_ttl）→ BLE operation.get | 终态 expired（+error 语义） |

## 2. 执行设计（吸取 cycle-1/2 全部教训）

1. **身份守卫**：每阶段开始前 `verify_identity` 六维校验（adv_addr /
   device_id / build_sha / SSID+IP / mqtt host:port / uptime），任一不符
   **拒绝操作**；无静默回退（choose_target 缺陷已绕开）；
2. **槽位台账**：async op 共 2-3 个（expired 1 + cancel 1 + 重试余量 1），
   ≤4 槽；终态 600s 保留期内不再造新 op，S6 结束后自然回收；
3. **变更台账**：仅 cycle-3 一次 mqtt_host/port 临时改指向（async 分支需要）
   → 采集 → 恢复 139.9.93.245:21883 → 轮询验证 connected=true；其余全部
   BLE 只读/tryconnect/cancel（tryconnect 失败或取消路径自恢复 persistent）；
4. **绝不 apply**：所有成功路径到 got_ip/trial ready 即止——不落盘、不改
   生产配置；cancel 或 300s 过期后设备自行回 persistent 配置；
5. **静置期利用**：300s 等待期间执行 trial cancel 分支与低风险只读采样，
   不延长窗口总时长（预计全程 ≈8-10 分钟）；
6. **帧完整性**：MQTT 请求唯一 id（d4ba28e 已修）；BLE/MQTT 全帧落盘；
   串口双 console 在录；结束 SHA256SUMS；
7. **job 粘滞窗口**：每个 async op 终态后预留 ≥90s 再发起下一个（cycle-1
   教训，脚本已内置）。
