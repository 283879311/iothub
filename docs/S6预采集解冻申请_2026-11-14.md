## 1. 目标分支与构造顺序（串行，依裁决 1→2→3）

| 序 | 分支 | 构造 | 预期 wire |
| --- | --- | --- | --- |
| 1 | **04b trial cancel** | async got_ip → 确认 trial ready → `network.cancel{trial_id}` → 采集 cancelled 语义 + trial idle | cancel 响应 `{trial_id, state:"cancelled"}`；trial 块 →idle |
| 2 | **04a expired** | 重新构造 async got_ip → **不 apply、不 cancel** → 静置 ≥300s（got_ip_ttl）→ 采集 expired 终态 | `state=expired`（+error 语义）；trial 过期清理副作用 →idle |
| 3 | **04c 段 A** | BLE sync tryconnect(CMCC-502+口令) → 阻塞至 got_ip → 采集受理响应 | `{trial_id, state:"got_ip", ssid}` 三字段+键序 |
| 4 | **04b trial 不匹配** | 构造尝试；协议上不可构造则如实记录"无法构造"及原因 | 实测为准 |

**P0 教训入档**：trial（`s_net_trial`）是共享单例候选，非每 op 独立——
expired 分支的 300s 窗口内不得创建第二个 trial、不得 cancel 第一个 trial。
300s 静置期间**只做只读采样**。

## 2. 串行执行设计

```
S0 身份守卫（六维，§3 基准）→ 串口确认在录 → 采集前置 device.status/config.get
S1 改指向（§5 台账）→ 等设备接入 mini_broker（≤75s）
S2 trial cancel 分支：
   op-1 = MQTT async tryconnect(CMCC-502+口令)
   → 等待 GOT_IP（连接+MQTT 回连+netcheck，预计 30-60s）
   → BLE operation.get（got_ip）+ network.status（trial ready 块）
   → BLE network.cancel{trial_id} → 采集响应
   → BLE operation.get（cancel 后实际状态，实测为准）+ network.status（trial idle）
   → op-1 收尾：diag.testhook{action:"try", to:"failed"}（BLE-only 测试钩子）
     强制终态 → cleanup(restore_persistent) + job clear（等待 ≥120s 并验证）
S3 expired 分支：
   op-2 = MQTT async tryconnect(CMCC-502+口令) → GOT_IP → 采集 ready 态
   → 不 apply / 不 cancel → 静置 ≥300s（期间每 60s 只读 device.status
     采样 stack min/low + heap，构成 low-list 口径证据链）
   → BLE operation.get（expired 终态）+ network.status（trial 过期清理→idle）
   → 自然 cleanup + job clear（等待 ≥120s 并验证）
S4 恢复指向（§5）→ 验证 TB:21883 connected
S5 04c 段 A：BLE sync tryconnect(CMCC-502+口令) → 采集受理响应帧
   → network.status（trial ready）→ BLE network.cancel{trial_id}（恢复 idle）
S6 trial 不匹配构造尝试（只读组合，不新增 op）
S7 结束态验收（§7）→ SHA256SUMS
```

每步 BLE 命令间隔 ≥0.25s（速率限制内置）；job 粘滞间隔 ≥90-120s 并以
"新 tryconnect 返回**新 op id**"作空闲确证（cycle-2 教训）。

## 3. 身份基准（目标设备：C8E4 单元，六维）

| 维度 | 基准值 | 不符处置 |
| --- | --- | --- |
| adv_addr / name | `B0:A7:32:28:C8:E6` / IotHubBLE-C8E4 | 拒绝操作（无静默回退） |
| device_id | `IotHub-C8E4` | 同上 |
| build_sha | `d4188551c`（1.3-dc254d5） | 同上 |
| SSID/IP | connected_ssid=`CMCC-502`；sta_connected=true；sta_ip=192.168.1.0/24（DHCP，记录精确值，不锁定尾数） | 同上 |
| mqtt host:port | `139.9.93.245:21883`（S1 前后按 §5 台账核对） | 同上 |
| uptime | 连续性：不出现新 boot（对照稳定窗口 boot≈19:44:32 与各阶段采样值） | 新 boot = 身份漂移 → STOP（§6） |

每阶段开始与结束各做一次六维校验并落盘（idcheck 帧）。

## 4. 槽位与操作台账（逐 op）

| op | 创建时点 | 终态方式 | 终态后保留 | 槽位/ job 释放条件 |
| --- | --- | --- | --- | --- |
| op-1 | S2（第 1 个 async） | `diag.testhook try→failed`（BLE 测试钩子，cancel 采集完成后） | 终态起 600s | cleanup 完成 + 新建 op 返回新 id（≥120s） |
| op-2 | S3（op-1 终态+清理确证后） | **自然 expired**（got_ip_ttl 300s）→ cleanup | 终态起 600s | 同上（≥120s） |
| op-3 | 无（sync 路径不建 op，已核） | — | — | — |

并发上限 1（任一时刻至多一个非终态 op）；总占用 ≤2/4 槽，无满表覆盖风险。
testhook 为 BLE-only 测试钩子（固件内建，生产无调用点），状态变更记入台账。

## 5. MQTT 临时改指向台账（唯一例外，cycle-3）

| 项 | 值 |
| --- | --- |
| 原值 | `mqtt_host=139.9.93.245` / `mqtt_port=21883`（tb_selfhost，1号 TB） |
| 临时值 | `mqtt_host=192.168.1.19` / `mqtt_port=21883`（PC LAN IP，mini_broker 本地 broker） |
| 修改入口 | S1：BLE `config.set{"patch":{"mqtt_host":"192.168.1.19","mqtt_port":21883}}`（effect=subsys，仅 MQTT 子系统软重启，非整机重启） |
| 恢复入口 | S4：BLE `config.set{"patch":{"mqtt_host":"139.9.93.245","mqtt_port":21883}}` |
| 恢复验证 | 轮询 `network.status.mqtt_connected=true`（≤80s）+ `config.get` 回读 host/port |
| **失败恢复** | 设备 75s 内未接入 mini_broker → **立即执行恢复入口** → 验证 → S6 中止归档；S2-S4 任一阶段中途失败且无法继续 → 优先执行恢复入口再中止；恢复入口自身失败 → 立即上报，不重试超过 2 次 |
| 持久化说明 | 该键持久化落盘（与前两轮一致），恢复后 NVS 终值 = 原值；前后帧全留档 |

## 6. 异常恢复规则（中途失败处置）

| 异常 | 处置 |
| --- | --- |
| 六维身份校验不符 / 新 boot | **立即 STOP**：若处于改指向状态先执行恢复入口，再归档上报；不做任何补救性设备操作 |
| BLE 断连 | harness 自动重连（≤3 次）；重连失败 → 恢复入口（如在改指向前）→ 归档上报 |
| cancel 无响应/超时 | 350ms 重试一次（速率限制内）；仍无响应 → **STOP 本阶段**：BLE 只读评估当前状态 → 执行恢复入口 → 归档 |
| op 未在 90s 内到达 GOT_IP | 采集实际状态；若 FAILED（netcheck 失败等）→ 该分支重试**至多一次**；再失败 → 中止 S6 归档上报 |
| got_ip 后 300s 内链路异常 | 只读记录，不干预；自然过期后按 expired 语义采集 |
| cleanup 后 120s 未恢复 persistent | STOP：恢复入口 → 归档上报（不手工断电） |
| mini_broker 异常退出 | 恢复入口 → 验证 → 归档上报 |
| 全程任何未列明异常 | 一律 STOP + 恢复入口 + 归档上报，不即兴处置 |

## 8. 冻结边界不变

不含：烧录、整机重启、NVS 直接写入、config.set 持久键（唯一例外=§5 的
mqtt_host/port 且恢复）、apply（任何成功路径到 got_ip/trial ready 即止）、
与其他验收并发。
