## 1. 双 TTL 时间线（v7 毫秒精度口径不变）

```
trial deadline     = esp_timer_get_time()/1000 + 300000   （store_trial 时刻起）
operation deadline = app_operation_now_ms()   + 300000   （set_state(GOT_IP) 时刻起）
Δ = T1 − T0 实际毫秒间隔（连接/netcheck 在 T0 之前，不计入）
trial deadline 不晚于 operation deadline；Δ>0ms 严格先到期，Δ=0ms 同时到期
T0/T1 无设备侧精确时间戳——主机 monotonic 区间取证，Δ 以测量区间报告
```

## 2. 分支与顺序（v8 三处修订加粗）

```
S0 **无条件 auth.login（本轮 token 计时起点；不设跳过选项）** → 六维身份守卫

   + 设备身份 + 采集时刻）

   sync tryconnect → 受理响应 → trial ready 采集
   → not_found 负向对照：operation.get{op-00000000CDEF1234} + 同刻 network.status
   → BLE cancel{trial_id} → cancelled 采集 → trial idle
S2 分支② BLE sync 04c 段 A（独立）：
   sync tryconnect → 原始受理响应帧+键序 → trial ready 采集
   → BLE cancel → trial idle
S3 分支④ BLE sync 专用 TTL（无 operation）：
   **token 年龄检查（≥480s → auth.login 续签①）**
   → sync tryconnect → trial ready（T0' 主机时钟）→ 不 cancel、保持 BLE 会话
   → T0'+270s 起每 15s 预到期采样（应仍 ready）
   → T0'+300s 起每 15s 查询至 idle（lazy clear 成对证据）
S4 分支⑤ MQTT async expired（唯一改指向段）：
   **token 年龄检查（≥480s → auth.login 续签②）**
   → 改指向（§5）→ 接入 mini_broker ≤75s
   → async tryconnect(CMCC-502+口令) → GOT_IP（主机时钟区间记录两转换）
   → S5d 机会性轮询（GOT_IP→EXPIRED 窗口内）：operation.get + network.status；
     "GOT_IP 且 trial idle" → 归档"清理原因未判定"（不称 trial 自身 TTL 捕获）
   → op-E 自然 EXPIRED → cleanup 确认（persistent 恢复）+ trial 终值记录
   → **op-V job clear 验证**：
     前置：BLE network.scan 完整性四条件——status=="ok"、BLE 响应全部分片
       完整接收、count==aps.length、完整 aps 中**不存在** __jobclear_probe__；
       任一不满足 → 视同未确认（重扫一次；仍不满足 → 走降级路径）
     → async tryconnect(__jobclear_probe__)，**不携带 idempotency_key**
     → **受理返回 operation_id 必须 ≠ op-E id**（新 id = op-E 的 s_net_async
       job 在受理前已清理的确证；返回 op-E id = job 未清 → STOP）
     → op-V 经 run 内 app_cmd_net_async_clear_job_sync() + 直接置
       FAILED/AP_NOT_FOUND 清除自身 job/cfg transaction——**不经 cleanup_fn**；
       若扫描发现 probe SSID（两轮均存在）→ **放弃 op-V，降级路径**：该项记
       "证据降级/未完成"，不得以完整 job-clear 已验证结论收尾
   → **token 年龄检查（≥480s → auth.login 续签③）——op-V 结束之后、恢复
     config.set 紧邻之前**
   → 恢复指向 → mqtt_connected=true（≤80s 超限 STOP）+ config.get 回读
S5 trial mismatch 分支：标"不可达/未覆盖"（不计入验收覆盖）
S6 结束态验收（§7）→ SHA256SUMS
```

## 6. 异常恢复规则（v7 + 扫描完整性增补）

身份漂移/新 boot → STOP（改指向状态先恢复）；BLE 断连 → 重连 ≤3 次 → 失败
按 §5 处置（分支④ 断连清 trial，作废重试至多一次）；cancel 无响应 → 重试
一次 → STOP；GOT_IP 90s 超时 → 重试至多一次；cleanup 后 120s 未恢复 → STOP；
auth.login 失败 → STOP；**扫描响应不满足完整性四条件 → 重扫一次 → 仍不满足
按降级路径处理；probe SSID 两轮均在 → 放弃 op-V 走降级并如实标注**；
**op-V 受理返回 op-E id → job 未清 → STOP**；恢复轮询 80s 超限 → STOP；
未列明异常一律 STOP + 恢复 + 归档，不即兴处置。
