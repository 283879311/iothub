## 1. 已实现（P0）

### 1.1 方向 4：`network.status` 暴露配置状态与持久规划

- 新增字段：`cfg_state`（static/dhcp/fallback/offline_pending_config/...）、`persistent_use_static`、`persistent_static_ip`。
- 新增 API：`app_wifi_get_cfg_state()` / `app_wifi_cfg_state_name_public()`（`main/wifi.c`，声明在 `main/config.h`）。
- 客户端可据此提示"救援网络、持久配置未生效"。

### 1.2 方向 3：恢复链候选重试（P0 止损层）

- `app_wifi_recover_from_apply_failure()` 新增 ⓪ 步：`lkg_equals(failed)`（候选==LKG==持久配置）时**重试候选一次**（`recover action=retry_candidate`），计入 attempts（恢复链 ≤3 约束不变）。
- 仍失败继续走原 LKG/DHCP 链；boot 路径同样受益但被 attempts 上界保护，无循环风险。
- 满足评审 D 用例约束：**只有候选==持久配置才允许重试候选**。

### 1.3 埋点 + 代际串扰修复（用户补充项）

- `WIFI_EVENT_STA_START` 处理器入口无条件打 `sta_start_evt gen=%u`——一次构建即可定性"事件丢失 vs 迟到"。
- **超时路径清 `s_wifi_apply_await_start`**：这是评审"代际串扰"担忧的实锤修复——原代码超时后 await 仍为 true，迟到的本代 STA_START 会在 `out_fail` 关门后执行 `offline_gate_clear_if_set()` 重新开门；或被下一代当成成功信号。修正后迟到事件走非 await 分支（门控下 ignored）。
