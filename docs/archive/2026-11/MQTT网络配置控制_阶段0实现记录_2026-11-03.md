## 1. 已实现

### 1.1 入口策略

- 新增 `main/cmd_policy.h/.c`：
  - `.async` 作为外部方法一律拒绝；
  - BLE/HTTP/MQTT 的 source/method 白名单；
  - MQTT v1 生产默认关闭；
  - cancel 双要素矩阵；
  - apply owner 必须与事务 owner 一致。
- `cmd.c` 在统一分派器入口执行策略，不再依赖各分支各自判断。

### 1.2 协议适配层

- 新增 `main/cmd_net_adapter.h` 与 `cmd.c` 内部 adapter API。
- BLE v1 `network.tryconnect/apply/cancel` 直接调用 adapter，不再构造 `.async` 方法字符串。
- MQTT 增加 v1 envelope（`version/id/cmd/args`）：
  - 阶段 0 只映射 `network.status`、`network.tryconnect`、`network.apply`、`network.cancel`、`operation.get`；
  - 其他 v1 命令返回 `unknown_command`；
  - adapter 上下文在进程内构造，`auth_level=LOCAL_TOKEN`；不从 JSON 读取 source/owner。
- 新增 `main/cmd_error.h/.c`，统一 v0 error → v1 code 映射；新增 `mqtt_unavailable`、`internet_unverified`、`static_ip_pinned`、`last_profile`。

### 1.3 owner / cancel

- `operation.h` 增加 `APP_OPERATION_OWNER_MQTT`。
- operation 创建时固定 owner；BLE 断连只处理 BLE owner，不释放 MQTT owner。
- cancel 同时校验调用者认证身份和 operation owner：
  - BLE 可取消 BLE/MQTT/HTTP；
  - MQTT 只取消 MQTT；
  - HTTP 只取消 HTTP；
  - 未认证/身份不明拒绝。
- `operation.get` 对 MQTT/HTTP 只返回本 owner 的事务。

### 1.4 配置事务门控

- 新增 `main/cmd_cfg_txn.h/.c`：
  - 单 active token；
  - token 不匹配不释放新事务；
  - 网络 operation/trial 持有 token；
  - `config.set`、`network.profile.delete` 通过 `app_config_lock` 门控。
- 同步 v0 trial 从试连开始持有 token，直到 apply/cancel/expire/BLE 断连。
- 异步 operation 从受理前持有 token，terminal/cleanup 释放。
- 事务期间 `config.set`、`web.auth.set`、profile 删除返回 `busy`。

### 1.5 profile 不变量

- `app_config_delete_wifi_profile`：删除后有效 profile 数为 0 时返回 `ESP_ERR_INVALID_STATE`，命令层映射 `last_profile`。
- 工厂复位 API 重命名为 `app_config_factory_clear_wifi_profiles`，仅 `bootstrap.c` 调用；普通删除不能通过该 API 绕过。
- invalid blob 恢复、snapshot rollback、底层 `count=0` 的语义在设计中区分，未改变现有恢复路径。

### 1.6 测试构建开关

- CMake 新增 `APP_CMD_MQTT_NET_TXN_TEST_BUILD`，默认 OFF。
- 只有同时定义 `APP_CMD_MQTT_NET_TXN_ENABLE=1` 和该测试标记时才编译通过；否则 `#error`。
- 生产构建 `device.info.build_variant = "mqtt_net_txn=off"`；测试构建为 `"mqtt_net_txn=test"`。
- 无运行时开关。

## 5. 需要评审确认的实现点

1. 配置门控复用现有递归 `app_config_lock`，没有新增独立长持锁；NVS 写入仍在该既有锁路径内。若要求完全不持锁做 NVS，需要单独改造 config 层，不属于阶段 0。
2. 同步 v0 trial 也在事务门控内；这会阻止 trial 期间其他通道 `config.set`，符合“事务期间统一 busy”。
3. MQTT v1 生产默认关闭；阶段 0 的设备测试若需要 MQTT owner 链路，必须用测试构建（`APP_CMD_MQTT_NET_TXN_TEST_BUILD=ON`），不能在生产构建打开。
4. `app_config_factory_clear_wifi_profiles` 仍是无运行时令牌的工厂复位 API；已从普通删除路径隔离并重命名，若要求更强的运行时防误用，需要再评审。
