## 1. 判据（含评审要求的连接年龄兜底）

**空闲起算 = max(最后应用层写入, 连接建立时刻)**。

- 若只用 `rx_age`：`s_last_rx_ms == 0` 时返回 `-1`（从未写入），"连上即被杀"的僵尸永远逃过 90s 判据——评审指出的唯一判据漏洞。
- 已新增 `s_conn_since_ms`（`on_connect` 置位，disconnect/reset 清零），`last_activity = max(s_last_rx_ms, s_conn_since_ms)`。

## 2. 触发条件与动作

全部满足才动作：

1. 已连接（`s_connected`）；
2. **无 notify 订阅**：`!s_data_subscribed && !s_cmd_subscribed`（硬条件）；
3. **无在途配网**：`app_ble_cmd_net_busy()` = 在途 net op 或打开的 cfg_txn（避免 reap → cancel → cleanup → restore 打断配网）；
4. 空闲 ≥ `APP_BLE_IDLE_TERMINATE_S = 90` 秒。

动作：`ble_gap_terminate(s_conn_handle, BLE_ERR_REM_USER_CONN_TERM /*0x13*/)`，随后走既有 `DISCONNECT` 路径（标志复位 + `app_bt_restart_advertising()`），广播自动恢复，无额外代码。失败不重试——下一秒 tick 时 idle 只会更大。

日志：`idle terminate conn=%u idle=%us (no subscribe, no app activity)`。

## 3. 载体

挂 diag 1s 节拍：`app_bt_adv_watchdog_poll()`（bt.c:507）内追加 `app_ble_gatts_idle_reap_poll()`，与广播看门狗同入口（跨任务调 NimBLE 的 host mutex 串行化先例已由该入口确立）。

## 5. 已知对价（记录在案）

- **已订阅后被杀的僵尸不回收**——这是"不误杀订阅后静默"的硬条件对价；二期可考虑订阅态长超时（如 10min），本批不做。
- 订阅后退订的僵尸会被正常收掉（合理）。

| # | 场景 | 判据 |

| R-BLE-1 | `kill`：连接 → 写一条 device.info → SIGKILL | ≤92s 出现 `idle terminate … idle=90..92s`；reason=0x13；随后广播恢复，`clean` 3/3 可连 |
