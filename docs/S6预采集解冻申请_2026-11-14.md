## 1. 目标分支与构造顺序（串行，真实生命周期）

| 序 | 分支 | 构造 |
| --- | --- | --- |
| 1 | **04b trial cancel**（op-1） | async got_ip → trial ready 采集 → `network.cancel{trial_id}` → cancelled 响应 + trial idle 采集 → **op-1 保持 GOT_IP** |
| 2 | **04a expired**（op-1 自然到期 + op-2 专造） | op-1 等待 GOT_IP TTL 自然到期 → 采集 expired 终态（cancel 后过期形态）→ 确认 cleanup/job clear；**再创建 op-2**：全新 got_ip、trial 保持 ready、不 apply 不 cancel → 静置 ≥300s → 采集 expired 终态（**含 trial 过期清理副作用**）→ 确认 cleanup/job clear |
| 3 | **04c 段 A**（无 op） | BLE sync tryconnect → `{trial_id, state:"got_ip", ssid}` + 键序 → trial ready 采集 → cancel 恢复 idle |
| 4 | **04b trial 不匹配** | 只读组合构造尝试；不可构造则记录原因 |

两个 expired 形态分开归档：op-1 = **cancel-后过期**（trial 已清、无清理副作用）、
op-2 = **trial 随行过期**（trial_ready 内部清理副作用→idle）——wire 可能不同，
正是评审要求的"不能把配置恢复成功与运行态恢复成功混为一谈"式的形态分离。

     （≥120s，"新建返回新 op id"确证）
S3 op-2（expired 分支）：
   MQTT async tryconnect → GOT_IP → ready 采集
   → 不 apply 不 cancel → 静置 ≥300s（同只读采样节奏）

## 5. MQTT 临时改指向台账（唯一例外，cycle-3）

| 项 | 值 |
| --- | --- |
| 原值 | `139.9.93.245:21883`（tb_selfhost） |
| 临时值 | `192.168.1.19:21883`（PC LAN IP，mini_broker） |
| 修改入口 | S1：BLE `config.set{"patch":{mqtt_host,mqtt_port}}`（effect=subsys 软重启 MQTT 子系统） |
| 恢复入口 | S4：BLE `config.set` 写回原值 + `network.status.mqtt_connected=true` 轮询（≤80s）+ `config.get` 回读 |
| **失败恢复（如实声明）** | 经策略核实（`app_cmd_patch_allowed`），**MQTT 源禁止写 CFG_DOMAIN_MQTT 键**——不存在 MQTT 备份写通道；UART 无 esp_console。**BLE 不可达 = 无自动恢复通道**：立即停止全部操作、mini_broker **保持运行**（设备保持接入、可观测、遥测不断）、串口与全部帧证据保全、立即上报人工接管；**不宣称已恢复**，恢复手段（现场 BLE 工具/断电）由评审现场决定 |
| 观测通道保留 | MQTT 源 status/operation.get = ALLOW（策略明示）：BLE 全灭期间仍可经 mini_broker 只读观测设备状态 |
| 暴露窗口 | 改指向自 S1 起至 S4 止（≈12–15 分钟），期间 BLE 每阶段校验存活 |

## 6. 异常恢复规则

| 异常 | 处置 |
| --- | --- |
| 六维校验不符 / 新 boot | **立即 STOP**（如在改指向状态先走恢复入口）→ 归档上报 |
| BLE 断连 | harness 自动重连 ≤3 次 → 成功：BLE 恢复入口；**失败：按 §5 失败恢复声明**——停止、保观测、上报人工接管，不假装已恢复 |
| cancel 无响应/超时 | 350ms 重试一次；仍无响应 → STOP 本阶段：只读评估 → 恢复入口 → 归档 |
| op 未在 90s 内到达 GOT_IP | 采集实际状态；FAILED → 该分支重试至多一次；再失败 → 中止归档 |
| cleanup 后 120s 未恢复 persistent | STOP → 恢复入口 → 归档（不手工断电） |
| mini_broker 异常退出 | 恢复入口 → 验证 → 归档 |
| 未列明异常 | 一律 STOP + 恢复入口 + 归档上报，不即兴处置 |

## 7. 结束态验收（收紧口径：配置恢复 ≠ 运行态恢复）

| 级别 | 判据 |
| --- | --- |
| **正常验收** | 恢复到**采集前记录的运行态**：connected_ssid=`CMCC-502`、sta_connected=true、mqtt_connected=true 且 host:port=139.9.93.245:21883（config.get 回读）、trial idle、无活动 op |
| **已知回落路径（单列）** | 若 cleanup 后落在 `TQ2026`（persistent 直连成功但运行态与采集前不同）——**单独记录，不判完全恢复**；必须解释与采集前状态的差异（persistent=TQ2026 而采集前运行态为 profile 回落 CMCC-502） |
| **禁止** | 为满足结束态而临时修改生产 profile（任何 config.set 换 SSID 均不允许） |
| 证据 | 每分支原始帧 + 串口区间 + idcheck 帧 + SHA256SUMS |

## 8. 冻结边界不变

不含：烧录、整机重启、NVS 直接写入、config.set 持久键（唯一例外=§5 且恢复）、
apply（成功路径到 got_ip/trial ready 即止）、任何绕过真实 cleanup 的人为终态
（testhook 类手段全部禁用）、与其他验收并发。
