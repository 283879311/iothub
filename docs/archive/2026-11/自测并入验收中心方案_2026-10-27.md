# 自测并入验收中心方案（评审稿，未实现）

> 日期：2026-10-27 · 适用：wx-ble-provision 小程序侧 · 分工：小程序侧由 WorkBuddy 执行，硬件侧不涉及
> 目标：把目前只能在上位机 Node 里跑的 12 套自测（739 项）中可移植的部分，收进验收中心，真机一键可跑、有账可查。
> **原则：自测 ≠ 验收。** 自测验证的是"引擎/逻辑在真机 JS 环境里也正确"（纯客户端，注入假设备），
> 验收验证的是"设备侧行为正确"（真机取证）。两者永远不互相替代，验收中心里分开展示、互不计入。

## 3. 方案 A 详细设计

### 3.1 单一事实源（关键改造）

- 用例代码从 `_verify/*-selftest.js` **下沉**到 `wx-ble-provision/utils/selftests/<suite>.js`，
  每套导出 `module.exports = { id, name, hostOnly, run(ctx) }`，`run` 返回
  `{ total, pass, fail, failures:[{name, detail}] }`。
- `_verify/*-selftest.js` 退化为**薄入口**：require 下沉后的套件 + host 专属环境（global.wx 桩、Page mock）+
  结果打印/退出码。**用例只写一份，host CI 与真机跑同一份**——这是整个方案的核心收益。
- 下沉时的用例改写规则：套件内不得直接引用 `global.wx`/`global.Page`，环境依赖一律通过
  `ctx`（`{ wxStub, pageMock, ... }`）注入；host 入口负责造桩，真机入口传空（真机天然有 wx）。

### 3.2 迷你 runner（无依赖）

- `utils/selftests/runner.js`：`runSuite(id)` / `runAll(portableOnly)`，逐套串行、
  单套失败不中断；`check(name, cond, extra)` 风格与现有 `_verify` 完全一致（改造时 diff 最小）。
- 每套记录耗时；全量 563 项纯逻辑预计 < 2s（无真机 IO），无需分批。

### 3.3 页面与接线

- 新增 `pages/selftest/selftest`（app.json 注册，主包 +1 页）：
  - 套件列表卡：名称 / 项数 / 上次结果（pass/ fail 计数 / hostOnly 灰显标注「仅上位机」）
  - 「运行本套」「运行全部可上机套件」两个按钮；运行中逐套更新，失败项**折叠展开**
  - 「复制报告」：纯文本（套件/项数/失败明细/耗时/时间戳），与 T4 报告同风格，直接可贴
- hub（pages/accept）SUBPAGES 数组加第 4 行：`自测 · 纯客户端回归`。
- 自测结果**不入 accept-store**（与验收账本隔离），页面内存态 + 复制导出即可。

### 3.4 与现有验收的边界展示

- 自测页顶部固定说明：「本页结果证明小程序端逻辑正确；设备侧行为以 T4/T5 取证为准，两者互不替代」。
- T4 报告格式不变；自测报告不进 T4 判定。

## 5. 风险与边界

1. **主包体积**：新增用例约 2500 行源码（<100KB），远低于 2MB 主包限制；若后续吃紧，测试套件可移分包，但当前不必。
2. **用例平移引入回归**：P1 平移后 host 全量必须仍是 739 项全绿（项数与断言逐条不变，只动环境注入方式）；任何项数变化都要在提交说明里解释。
3. **真机环境差异**：`Date.now`/`Math.imul`/JSON 行为一致，无已知分叉点；pframe 的 CRC/LCG 向量在真机重跑本身就是一次跨环境一致性验证（有额外收益）。
4. **不过度自动化**：需要真设备、真 BLE 的断言（T4/T5/stress 页）不搬进自测页；`acceptance-selftest` 下沉的是"runner 纯逻辑 + 受控改密流程状态机"部分，设备腿仍在 T4。
