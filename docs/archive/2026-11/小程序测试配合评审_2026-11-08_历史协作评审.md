## A. 判据缺口（建议修，按优先级）

### A1【P1】`expired` 不在 op 终态集合 —— 会把设备正常到期轮询成客户端超时

- 固件 got_ip TTL（300s）到期产出终态 **`state:"expired"` + `error:"timeout"`**
  （wire 实证 2026-11-08 12:2x，op-24B7：`{"state":"expired","error":"timeout","stages":{...全true}}`）。
- `utils/bmirror.js:30` `OP_TERMINAL = ['success','failed','cancelled']`——缺 `expired`；
  用于 `bmirror.js:573` 轮询跳出条件 → op 到期后轮询**不跳出**，空转到 deadline，
  上报"客户端超时"而非干净的设备终态。
- `utils/acceptance.js:1976` `waitOpTerminal` 同病：只 break 于
  `failed | got_ip | cancelled`——`expired` 落空转。
- `utils/provision.js` 已正确处理（STATE_TEXT 含 expired、终态判断含 expired:205）——两处对齐它即可。
- 触发场景：apply 迟迟未发（BLE 掉链/用户中断）→ op 滞留 got_ip 300s → 到期。

### A2【P2】provision 成功判据不等联网验证 —— 与自家 #13 卡口径不一致

- `utils/provision.js:278` 返回成功条件 = `hasIp && !mismatch`（+ connected_ssid 一致），
  **不含 `internet_verified` / `mqtt_connected`**。
- 而 T4 #13 卡判据是"等 sta_has_ip=true **且 mqtt_connected=true**"。apply 后设备要
  重放配置 + 主路径重验（netcheck 1-3s），瞬态窗口内返回成功，理论上会与 R2
  netcheck-fail→rescue 回滚竞态（小概率，但 #13 卡口径是对的）。
- 建议：成功条件加 `st.internet_verified === true`（60s 预算内等待，等不到按现有
  pending 路径返回）。

### A3【P2】errors.js 缺 `wifi_config_offline` 文案

- `TEXT`/`HINT` 均无此码 → 用户看到裸码。今日已定性：cancel 清理 restore 窗口的
  **瞬态码，重发即恢复**（T4 #12 + 串口 442079 实证）。
- 建议文案："设备正在恢复网络配置（取消/过期清理中），请等 2-3 秒重试"；
  HINT："瞬态码非缺陷；连续出现超过 3 次才需排查"。

### A4【P2】busy→cancel→立即重试可能撞 restore 窗

- `utils/provision.js:141-153`：busy 时取消上一个 op 后**立即** tryConnect。cancel
  返回 ≠ 清理收敛（restore_persistent 的 apply 危险窗实测 2-6s），重试可吃
  `wifi_config_offline` 或再次 busy。
- 建议：重试结果若为 busy/wifi_config_offline，等 1-2s 再试一次（与
  `retryTryconnectAbsent` 的 backoff [1,2,3s] 纪律一致，注意那次重试即可，别抹平真缺陷）。

## B. 维护性 / 取证建议

### B1【P3】固件行号引用会漂移

bmirror.js 注释硬引用 `wifi.c:1574-1587 / 2048 / 2069 / 3669`、`cmd.c:413/755-760` 等
——固件每次提交行号即漂移（今天已漂过一轮）。建议以**函数名**为主
（`app_wifi_tryconnect_classify_reason` / `app_wifi_tryconnect_entry_blocked` /
`app_wifi_tryconnect_on_disconnected` 等），行号为辅。

### B2【P3】时间线与串口对时：固件现成字段没用上

- provision 时间线（timelineText）是墙钟；硬件串口是 `I (uptime)`——每次联合定因
  都要人工换算 boot 时刻（今天三起事故全靠这个对时）。
- **device.info 已暴露 `uptime_ms` + `reset_reason`**（固件 cmd.c:1219-1220，现成）。
  建议：`timelineReset()` 时读一次 device.info 记 `boot_wallclock = now - uptime_ms`，
  每条事件附 `devUptime` 列 → 时间线可与串口日志**逐行对齐**。
