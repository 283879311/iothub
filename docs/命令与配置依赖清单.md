# 命令与配置依赖清单（阶段 1）

> 范围：`main/cmd.c`、`main/ble_cmd.c`、`main/mqtt.c`、`main/http_*.c`、`main/config_apply.c`、`main/config.c`、`main/wifi.c`。
> 目的：先固定现有入口、执行函数、状态修改、NVS 持久化、副作用和权限，再决定异步配网与配置事务怎么改。
>
> 本轮只做盘点，不改代码。状态：✅ 已实现/已实测；🟡 部分实现；❌ 未实现；— 不适用。

## 1. 通信入口与认证

| 入口 | 协议位置 | 认证 | 执行核心 | 备注 |
| --- | --- | --- | --- | --- |
| BLE CMD | RX `6E400004`，TX `6E400005` | `login` token，TTL 600s，连接级失效 | `app_cmd_execute_ex(APP_CMD_SOURCE_BLE)` | 单行上限 512B，队列深度 8，CMD 任务栈 4096；当前 `SM_LVL=0`，无链路加密/绑定 |
| MQTT RPC | `v1/devices/me/rpc/request/+`、`iothub/rpc` | broker 设备 token | `app_cmd_execute_ex(APP_CMD_SOURCE_MQTT)` | RPC 限频约 5 次/秒；响应发布后按 `reboot_after_response` 重启 |
| HTTP Command | `POST /api/v1/command` | Cookie/Basic（`app_http_require_auth`） | `app_cmd_execute_ex(APP_CMD_SOURCE_HTTP)` | 返回 `{id,ok,result/error}`；响应发送后按需重启 |
| UART | 外部设备数据 | 无命令认证 | 不进入 `cmd.c` | UART 是数据面；`uart.send` 只是命令层向 UART 写入 |

## 5. 配置字段与持久化

主配置 blob：NVS 命名空间 `iothub`，键 `runtime_cfg`，结构 `app_config_t`，当前版本 11。

| 域 | 字段 | effect | 持久化 | 生效函数 | 当前问题 |
| --- | --- | --- | --- | --- | --- |
| GPIO | `relay_power_policy`、`led_power_policy`、极性 | none/reboot | 主 blob | `app_io_apply_policies_at_runtime` / 重启 | 策略与输出状态分属两套存储 |
| MQTT | backend/host/port/token/use_tls | subsys | 主 blob | `app_mqtt_schedule_restart` | token 明文在 NVS；连接失败不回滚配置 |
| NET | net_mode/ap_*/sta_*/static IP | reboot | 主 blob + `wifi_profiles` | 仅落盘，调用方重启 | 无候选/试连/回滚；profile 另存；保存后重启可能失联 |
| UART | baud/data/stop/parity | subsys | 主 blob | **`config_apply` 未接线**；HTTP 专用 handler 应用/保存/回滚 | `config.set` 提交 UART 字段会被拒绝 |
| BT | role/device_name | reboot | 主 blob | 落盘后重启 | `config.set` 未复用托管名逻辑；MQTT 可改 |
| WEB_AUTH | username | none | 主 blob | 即时 | 口令走独立哈希接口；命令层不作废旧会话 |
| DATAPIPE | data_route_* | none | 主 blob | `data_pipe_apply_routes` | MQTT 可改 |
| 配网 PIN | `ble_prov/pop` | 下次配网 | 独立 NVS | 探针启动时读取 | 主固件不消费；BLE L2 未实现 |
| 探针标记 | `ble_prov/done` | 下次启动 | 独立 NVS | 探针判断 | 恢复出厂已清除 |
| 输出记忆 | `io_relay_last`、`io_led_last` | 上电恢复 | 独立 NVS | `app_io_boot_apply` | 仅 `POWER_RESTORE` 策略写 |

## 6. 当前权限与目标矩阵差异

| 命令/能力 | 当前实际 | 目标 |
| --- | --- | --- |
| `config.get` / 状态读取 | HTTP/BLE/MQTT | 保持，按字段脱敏 |
| GPIO/继电器/LED | HTTP/BLE/MQTT | 保持，控制可按策略限制 |
| `uart.send` | HTTP/BLE/**MQTT** | HTTP/BLE；MQTT 默认禁止 |
| `uart` 配置 | 仅 HTTP 专用端点 | HTTP/BLE 通过 `config.set`/UART 域 |
| Wi-Fi 配置/试连 | HTTP/BLE；MQTT 拒绝 | 仅本地；试连需候选状态机 |
| MQTT host/token | HTTP/BLE；MQTT 拒绝 | 仅本地 |
| 蓝牙角色/名称 | HTTP/BLE/**MQTT**（`config.set`） | 仅本地或 L2 |
| 管理员凭据 | HTTP/BLE；MQTT 拒绝 | 仅本地/L2，改后作废旧会话 |
| 配网 PIN | HTTP/BLE + 管理员口令 | 保持，补 L2 链路安全 |
| 数据面回环 | HTTP/BLE/**MQTT** | 仅本地 |
| 重启/恢复出厂 | BOOT/HTTP OTA 路径 | 受保护命令，明确确认 |

## 7. 当前事务与失败边界

| 域 | 当前顺序 | 失败行为 | 目标 |
| --- | --- | --- | --- |
| GPIO | 校验 → 保存 → 应用策略 | 应用失败保留旧运行态 | 保持 |
| MQTT | 校验 → 保存 → 子系统重启 | 保存成功但连不上保留新配置，状态上报 | 区分“配置成功”和“连接恢复” |
| UART | HTTP handler：应用硬件 → 保存；失败回滚 | 命令层未接入 | 统一为校验/保存/应用/回滚 |
| NET | 校验 → 保存 → 调用方重启 | **未试连**；保存后无法恢复旧配置；profile 另存 | 候选试连 → 拿 IP → 提交 → 失败恢复 |
| BT | 保存 → 重启 | 无热重配 | 保持 |
| WebAuth | 校验旧口令 → 保存哈希 → 作废旧会话（HTTP） | 命令层不作废 | 统一 |
| 配网 PIN | 校验 → 写 NVS | 不回显 | 保持 |

## 8. 阶段 1 结论与下一步

**优先修正的不是 OTA，而是网络/配置的提交边界。**

1. 把 `network.*` 命令冻结为：`network.status`、`network.validate`、`network.tryconnect`、`network.cancel`、`network.apply`、`network.reconnect`、`network.profile.list/delete`、`network.scan`。
2. 在现有 `wifi.c` 事件循环上增加候选状态（`IDLE/CONNECTING/GOT_IP/COMMITTING/SUCCESS/FAILED/CANCELLED`），不新建常驻任务；BLE 回调只投递，不阻塞等待。
3. `network.apply` 只接受已获得 IP 的候选，保存主配置和 profile；失败恢复旧配置。MQTT 重连与网络提交分开报告。
4. 修正权限差异：`uart.send`、`data.loopback`、BT 配置不能再由 MQTT 直接修改；网络写操作只允许本地。
5. UART 配置要么接入 `config_apply`，要么明确保留 HTTP 专用路径；不能继续出现“命令表宣称支持、`config.set` 实际拒绝”的状态。
6. Web 旧端点继续保留，作为双跑回退；在 BLE 命令等价能力通过前不删除。

验收基线：BLE 命令完成扫描、校验、试连、取消、提交、失败恢复；过程中 BLE 控制/数据通道仍可用；记录试连期间 `free/largest` 最低值；错误密码、AP 不存在、超时、旧配置恢复各有明确结果。
