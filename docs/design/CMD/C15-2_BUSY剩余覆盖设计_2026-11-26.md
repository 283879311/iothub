# C15-2 剩余覆盖设计（begin / trial / 终态 job_op）与遗留观察（2026-11-26）

> 文档状态：DESIGN_CANDIDATE（未实施）。适用范围：CMD-15 / C15-2 诊断剩余覆盖。
> 前置事实：变更 A（`5aaabea`）已入 `main`；accept-snapshot 分支已在设备受控复现中验证；原始残留 BUSY 未解释，现场已随重烧清除。

## 1. 已有结论

- 诊断功能在设备上可用：`branch=accept`、`job_active=1`、`job_op_valid=1`、`active_ops=1`、无截断。
- 该实验只验证 accept-snapshot 分支和 job/operation 关联，不解释原始 BUSY。
- begin/trial 分支、终态 `job_op` 尚无设备证据。

## 2. 实验 1：begin 分支（active operation 拒绝）

**目标诊断字段**

- `branch=begin`
- `job_active_before=0`
- `start_attempted=1`
- `start_err=ESP_ERR_INVALID_STATE`
- `mapped_busy_source=begin_operation_active`
- `active_ops>=1`

**候选触发路径**

1. 建立一次 `network.tryconnect`；
2. 发起 `network.cancel`，在 cleanup 已清理 job、但 operation 尚未进入终态的窗口内，立即发起第二次 `network.tryconnect`；
3. 第二次应进入 `begin`，看到 job 已清、operation 仍 active。

**可行性**

- 窗口位于 cleanup 的 job clear 与 `app_operation_set_state(CANCELLED)` 之间，天然很窄；
- 现有 `APP_C1_TEST_HOOKS` 可在 cleanup 返回、finalize 前暂停，但诊断构建当前未启用该宏；若使用，需单独构建组合（`APP_C15_BUSY_DIAG + APP_C1_TEST_HOOKS`）并审查；
- 不建议仅靠外部时序盲试，容易得到不可解释结果。

**恢复/停止**

- cancel 后等待终态 `cancelled`/`cleanup=ok`；
- 若第二次被受理而非 busy，立即 cancel 两次操作并停止；
- 任一 cleanup 异常/网络未恢复即停止。

**状态**：`NOT_IMPLEMENTED / 需 hook 设计评审`。

## 3. 实验 2：trial 分支

**目标诊断字段**

- `branch=trial`
- `busy_gate=1`
- `job_active=0`（或 job 与 trial 的关联按实际记录）
- `mapped_busy_source=trial`

**候选触发路径**

1. 使用当前 SSID + 正确口令发起 `network.tryconnect`，等待 `got_ip`（产生 trial，不 apply）；
2. 在其 TTL 内发起第二次 `network.tryconnect`；
3. 第二次应命中 `trial_busy()`。

**可行性**

- 需要正确 Wi-Fi 口令（仅从 `.local/test-env.md` 读取，不进日志）；
- 第一次 tryconnect 会切换/重连 STA，但目标仍是当前 SSID；trial 保持期间网络可能处于候选状态；
- 恢复需 cancel 第一次 operation 或等待 trial TTL；必须确认 trial 清理与 STA 恢复。

**风险**

- 涉及真实口令与 trial 生命周期；比 accept 实验影响面大；
- 不得把 trial 写入持久配置；不得 apply。

**状态**：`NOT_IMPLEMENTED / 需单独设备授权`。

## 4. 实验 3：终态 job_op

**目标诊断字段**

- `job_active=1`
- `job_op_valid=1`
- `job_op_state` 为终态（failed/cancelled/expired）
- `job_op_cleanup` 记录实际值

**可行性**

- 正常 cleanup 会先清 job 再置终态，因此“job active + op 终态”大概率只在异常/竞态窗口出现；
- 通过公开命令难以稳定构造；需要 fault injection 或 cleanup 暂停 hook，属于新的测试设计；
- Host D04 已覆盖格式化输出，但设备侧触发条件未定义。

**状态**：`NOT_IMPLEMENTED / 可能只能记为 NOT_COVERED`。

## 5. 遗留观察

### 5.1 原始残留 BUSY

- 2026-11-26 设备在无已知 operation ID 可查询的情况下返回 BUSY；
- 只读接口无法枚举 job/active op；重启后现场清除；
- 结论保持“未解释”，不得写成已定位或已修复。

### 5.2 BLE 大响应丢分片

- `device.status`（约 1.3 KB）与 `config.get`（约 1 KB）在当前负载下连续出现分片未完整到达；
- `device.info`（286 B）与 `network.status`（531 B）正常；
- 探针已改用小响应读取；该现象作为独立 BLE 传输可靠性观察记录，不与 C15-2 结果混合。

## 6. 边界

- 本文只定义实验设计，不修改代码、Contract 或设备；
- 不启动 P2；
- 任何设备触发需单独授权，并分别记录触发、恢复、停止条件；
- begin/trial/terminal job_op 未完成前，C15-2 保持 `BUSY_REJECTED / NOT_COVERED`，CMD-15 保持 `TEST_PENDING`。
