## 1. 改动（一处，cmd.c；2026-11-06 返工版）

```c
#define APP_CMD_SCAN_MIN_INTERVAL_MS 3000
static int64_t s_last_scan_end_ms = 0;      /* 记"上一次扫描结束"时刻 */

static bool app_cmd_scan_gate_check(void)   /* 只读，不改状态 */
{
    now = esp_timer_get_time()/1000;
    allow = (s_last_scan_end_ms == 0) || (now - s_last_scan_end_ms >= 3000);
    return allow;
}

static void app_cmd_scan_gate_stamp(void)   /* 扫描返回后调用，成败都盖 */
{
    s_last_scan_end_ms = esp_timer_get_time()/1000;
}
```

`network.scan` 分支：

```c
if (source == APP_CMD_SOURCE_MQTT) {
    err = "guard_rejected";
} else if (!app_cmd_scan_gate_check()) {
    err = "busy";                       /* 距上次扫描结束 <3s */
} else if (app_wifi_perform_scan_command() != ESP_OK) {
    app_cmd_scan_gate_stamp();          /* 失败同样占用过射频 */
    err = "wifi_scan_failed";
} else {
    app_cmd_scan_gate_stamp();
    ... 组回包 ...
}
```

**返工原因（评审）**：旧实现"允许时即盖戳"，而单次扫描本身约 5.8s，串行调用两次开始间隔恒 >3s，闸门永不拒绝——等于 no-op。改为**以扫描结束时刻计冷却**，才真正保证两次扫描之间射频空闲 ≥3s。

其余不变：首次扫描不受限；MQTT 源仍 `guard_rejected` 且不消耗冷却；错误码用既有 `busy`。

## 2. 时间预算

10 次连续 scan（含 3s 冷却）≈ 10×5.8s + 9×3s ≈ **85s** < T4 用例 4 的 120s BUDGET。小程序侧已按评审同步放宽 BUDGET 以留余量。
