## 1. 评审改形（已按此实现）

| 评审结论 | 实现 |
| --- | --- |
| 同步等 PUBACK 会死锁：publish 在 esp-mqtt 事件任务内联执行，PUBACK 也要该任务派发 | **改事件驱动闸门**：publish 记 `msg_id` + 1s `esp_timer` 兜底；`MQTT_EVENT_PUBLISHED` 匹配即提前放行；等待发生在 **mqtt_restart 任务**，事件任务全程不阻塞 |
| TTL 缩短打错对象：孤儿在 ACCEPTED 态（20s），300s 是 GOT_IP_TTL；过期链已调 `defer_restart_end` | **撤回**：不改 TTL、不加 `trial_expired`；改为验收时观察 `expire ... cleanup=ok` 是否出现，区分"窗口内自愈"与"worker 悬挂" |
| +4.95s 提前放行未知 | 各 `defer_restart_end` 调用点改调 `app_mqtt_defer_restart_end_at(site)`，输出 `defer_end site=… depth_before=…`，用于实现期定性 |
| PUBACK 钩子点现成（`mqtt.c:1228` 记 `last_msg_id`） | 已在该分支前置 `app_mqtt_ack_gate_on_published()` |

## 2. 代码改动

`main/mqtt.c`

- 新增闸门状态：`s_pending_resp_msg_id`、`s_ack_gate_events`（静态事件组）、`s_ack_gate_timer`、`APP_MQTT_ACK_GATE_TIMEOUT_MS=1000`。
- `app_mqtt_publish_command_response()`：捕获 `esp_mqtt_client_publish()` 返回值；**仅当 `app_mqtt_restart_is_deferred()`**（网络事务在飞）时武装闸门。
- `app_mqtt_ack_gate_on_published(msg_id)`：`MQTT_EVENT_PUBLISHED` 里比对并提前放行，日志 `resp acked msg_id=N`。
- `app_mqtt_ack_gate_timeout()`：1s 兜底，日志 `resp_ack_timeout msg_id=N` 后照样放行（不阻塞、不失败）。
- `app_mqtt_wait_resp_ack_gate()`：插入 `mqtt_restart` 任务 **`app_mqtt_apply_config()` 之前**（`mqtt.c` restart 循环），有未确认回包时最多等 1.2s，日志 `resp ack gate released msg_id=N (acked|timeout)`。
- `app_mqtt_defer_restart_end_at(site)`：诊断版释放入口，多打一行 `defer_end site=…`。

`main/operation.c`

- 8 个生产调用点改调 `_at()`：`op_create/busy`、`op_create/no_slot`、`op_create/error`、`op_set_state/terminal`、`op_cancel/cleanup_failed`、`op_cancel/terminal`、`worker/run_failed`、`expire/terminal`（`operation.c:982` 的 C1 基线代码不动）。

`tools/ble_p0/mqtt_ack_gate_inject.py`（新增）

- 最小 MQTT 3.1.1 注入 broker，三种模式：
  - `--mode cut`：设备发回包时**立即断链且不回 PUBACK**（受理瞬间断连）；
  - `--mode withhold`：不回收任何 PUBACK（制造 inflight/outbox 积压）后下发 tryconnect；
  - `--mode normal`：正常 PUBACK（对照）。
- 订阅建立后 `--delay` 秒下发 `network.tryconnect`，观察串口三条日志即可判定闸门行为。

## 5. 风险（如实记录）

- 重积压时 1s 兜底会先到、回包仍可能丢（设计如此），由 V3 的自愈链兜底；闸门只缩短窗口，不保证 100% 送达。
- 闸门只对"网络事务在飞"（defer 生效）时的命令回包生效，查询类命令零影响。
- 若某次 restart 在闸门武装前执行，窗口不变（~20ms），属残余竞态，记录在案。
- 诊断日志 `defer_end site=` 目前常开（每次终态一行），验收后可按需降级为 DEBUG。

## 6. r2 调整（评审后实现）

### 6.1 001：等待点前移到 tryconnect worker

r1 的闸门插在 MQTT 重启任务，而现场拆链是 **trial 自己的 WiFi 断连**（`wifi: run -> init` → `STA_DISCONNECTED → app_mqtt_stop()`，不经过重启任务）。r2 改为在 `app_cmd_net_async_run()`（cmd.c）里、调用 `app_wifi_try_connect_ip()` **之前**做两段等待：

1. `app_mqtt_resp_delivery_begin()` 清 `published` 位；
2. `app_mqtt_wait_resp_delivery()`：
   - 等 `APP_MQTT_RESP_PUBLISHED_BIT`（publish 后无条件置位，上限 **300ms**）；
   - 再走原 `app_mqtt_wait_resp_ack_gate()`（上限 **1.2s**）。
3. MQTT 重启点的闸门**保留**作第二道（覆盖配置变更类 rebuild）。

最坏附加 ~1.5s，试验 TTL 20s。武装竞态处理：若 publish 早于 begin，清位只损失 300ms，随后 ack 闸门仍持有已武装的 pending，功能不受影响。

### 6.2 002 短期：独立过期任务

`main/operation.c` 新增 `op_expire` 任务（`xTaskCreate`，3072B，prio 4，1s 节拍只跑 `app_operation_expire_one()`），与主 worker 解耦。**不用 esp_timer**（`expire_one` 同步调 `cleanup_fn`，可能阻塞）。并发安全依赖既有 `expiring` 闸 + generation 比对（R3/R4 评审前提）。创建失败会打 `expire task create failed (TTL safety net disabled)`。
