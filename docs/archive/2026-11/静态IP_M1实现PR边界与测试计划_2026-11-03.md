语义约束：

- `app_wifi_apply_cfg()` 返回后 `*stage_out` 必为最后执行阶段；失败时保留首个失败（调用侧只在 `failure.valid==false` 时写入）。
- `app_wifi_lkg_capture()` 仅在 `app_wifi_apply_cfg()` 成功返回后调用。
- `app_wifi_apply_dhcp_rescue()` 复制 `base` 的 SSID/口令，强制 `sta_use_static=false`，静态字段不参与；不改 `s_config`。
- `app_wifi_enter_offline()` 严格按 §3.6 顺序：置标志 → 停窗口 → `esp_wifi_stop` → 记录状态。
- `app_wifi_connect_begin/end()` 只包裹**自动**连接调用点（1–4 号）；`begin()` 在同一临界区内完成"检查离线 + `inflight++`"，只有返回 true 才允许调用 `esp_wifi_connect()`；`app_wifi_wait_connect_inflight()` 在离线切换停 Wi-Fi 前调用，200ms 告警、1000ms 上限，未归零不得 stop。
- `begin()` 只负责离线门控与 in-flight 计数；`net_mode`、auto-connect suspend、tryconnect 占用等其他前置条件仍由各调用点判断，不并入该临界区（避免改变既有语义）。

## 8. 风险与回退

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 改断开事件处理器影响 tryconnect 归属 | 冻结补丁回归 | 门控加在归属检查之后；`s_wifi_cfg_offline==false` 时行为逐字节不变；重跑 tryconnect 回归子集 |
| LKG 过期（`config.set` 后未重启） | 运行期恢复可能回到旧网络 | M1 明确只保证运行连续性；持久正确性由 M4 的 VALID/pending 解决 |
| 每次启动静态失败都先尝试再救援 | 启动多花数秒 | 有界、单次；M4 加启动周期计数与熔断 |
| 注入构建与正式构建行为差异 | 验收代表性 | 正式构建跑 T1/T2/T11/T12；注入仅用于故障路径 |
| 测试设备 NVS 残留非法配置 | 设备反复进入救援 | 测后恢复并验证；保留 `config.get` 快照 |

**回退**：撤销 PR 即可恢复旧行为（旧行为是 abort 风险，回退仅用于开发期）；测试设备可擦 NVS 或重烧正式固件。
