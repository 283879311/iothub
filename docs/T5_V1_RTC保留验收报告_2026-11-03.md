# T5 V1：RTC_NOINIT 一次性票据（软件复位）验收报告
> **状态**：ARCHIVED（文档状态标定 2026-11-14，定义与索引见 [docs/README.md](README.md)）


> 结论：**PASS（2026-11-03）**。范围仅限 `esp_restart` 软件复位路径；EN 硬复位与掉电未验证，T5/T6 故障注入未执行。
> 设备：C8E4（MAC `b0:a7:32:28:c8:e4`）；65D8 未参与，保持正式 M1 + DHCP。

## 1. 验证对象

测试专用 RTC 票据（`APP_WIFI_FAULT_INJECT`）：
- `diag.m1hook action=rtc_probe` 写入 `stage=0xFFFF,count=0` 票据；
- `action=reboot` 经 `app_reboot_schedule()` 延迟 1.5s `esp_restart`；
- 启动最早消费票据（读→校验→清 RTC→seed RAM），一次性；
- 正式构建不包含任何票据代码/入口。

## 2. 四阶段结果

| 阶段 | 内容 | 结果 | 关键证据 |
| --- | --- | --- | --- |
| 关口一 | hooks app 烧写（`0x10000`），同一 bootloader 会话 NVS A/B | PASS | A/B SHA 均 `bb3628c5…`，逐字节一致；esptool `Hash of data verified` |
| 阶段一 | 写 `rtc_probe`，等待 12s | PASS | `reboot_required=true`；`boot_ticket_armed stage=65535 count=0` ×1；`rst:0x`=0；BLE 仍可查询 |
| 阶段二 | 软件复位 + 首次消费 | PASS | `reboot_scheduled=true`；`rst:0xc (SW_CPU_RESET)` ×1；`ticket_seen=1 probe=1` ×1；静态 `.50`、MQTT |
| 阶段三 | 第二次软件复位 | PASS | `rst:0xc` ×1；`ticket_seen=1 probe=1` **0 次**；静态 `.50`、MQTT |
| 阶段四 | 恢复正式 M1 | PASS | BIN `b0e6d6c7…` 完整 SHA 一致；`1.2-a35eef9-dirty`；`.50`、MQTT；`diag.m1hook` → `unknown_method` |

## 3. 票据生命周期（已验证）

```text
rtc_probe 写入 stage=0xFFFF,count=0
  → 12s 无自动复位
  → esp_restart（rst:0xc）
  → ticket_seen=1 probe=1（恰好一次）
  → esp_restart（rst:0xc）
  → ticket_seen=1 probe=1 = 0（不重复）
```

结论：软件复位路径下 RTC_NOINIT 票据可保留、可消费、不可重复触发。

## 4. NVS 判据说明

- 跨启动原始 16 KiB 对比**不成立**：每次应用启动时 Wi-Fi 栈会写 NVS（页状态/内容变化已实测）；
- 关口一采用**同一 bootloader 会话** `read A → write app → read B`（全程 `--before/--after no_reset`），隔离“写 app”动作；
- A/B 一致证明烧写 app 未改变 NVS；逻辑配置由 BLE 回读确认；
- T3 原始基线 `62cc5747…` 与新快照 `2a292548…` 均保留为历史证据。

## 5. 未验证边界（不得外推）

- EN 引脚硬复位后的票据保留（V2 待立项/批准）；
- 掉电再上电后的票据行为；
- T5（`static_set_ip`）与 T6（`static_dhcpc_stop`）启动期故障注入的完整恢复链；
- 不同复位原因下 RTC 内容的普遍可靠性。

V1 PASS **不**代表所有复位类型可靠，也不代表 T5/T6 已通过。
