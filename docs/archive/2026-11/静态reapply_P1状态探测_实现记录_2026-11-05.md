## 1. 改了什么

### 1.1 方向 2：状态探测替代“干等事件”

`main/wifi.c`

- 新增常量：`APP_WIFI_START_PROBE_TOTAL_MS = 4000`、`APP_WIFI_START_PROBE_INTERVAL_MS = 100`（原 `APP_WIFI_START_WAIT_MS = 2000` 删除）。
- 新增无副作用探测 `app_wifi_sta_driver_started_probe()`：
  ```c
  esp_err_t err = esp_wifi_sta_get_ap_info(&ap);
  return err == ESP_OK || err == ESP_ERR_WIFI_NOT_CONNECT;
  ```
  契约来自 `esp_wifi.h`：`ESP_OK`=已连接、`ESP_ERR_WIFI_NOT_CONNECT`=已启动未连接；因此这两个返回等价于“STA_START 语义已完成，只差连接”。
- apply 等待循环改为：事件位只作唤醒（50ms 粒度），每 100ms 探测一次；探测命中后在**同一临界区**消费 `await`，随后按 STA_START 处理器的 A8 顺序收尾：`startup_connect_window → offline_gate_clear → apply_hold_clear → schedule_connect_task(0) → completed_gen=gen → set event bit`。
- 日志：`apply_start_probe gen=N t=<ms> driver_started=1`。
- **探测未命中时行为与 P0 完全一致**（4s 后走原超时 → 恢复链 → `retry_candidate`），因此这是纯增益改造，不新增失败面。

### 1.2 代号标注修正

`sta_start_evt` 日志从 `gen=N` 扩展为：

```
sta_start_evt gen=%u await=%d consumed=%u completed=%u
```

`await=0` 明确表示“这是迟到/重复事件，不会被当成本代完成信号”。P0 阶段观察到的“同一代号两次事件”由此可判读。

### 1.3 attempts 不变式注释更正

`main/wifi.c` 两处注释更新为：候选 / 候选重试 / LKG / DHCP 救援各计 1，**单周期上界 4**；`attempts` 只是计数、无硬门控，恢复链只走一次且不递归，不存在循环。（P0 记录 §5 的偏差项，本条只是注释，不影响二进制语义。）

### 1.4 验收中修掉的两个自引入缺陷

1. **`conn_find` 恒为 7**：初版用 `ble_gap_conn_find(BLE_HS_CONN_HANDLE_NONE, …)`，但 NimBLE 的该接口是精确句柄匹配、`NONE` 不是通配 → 改为用本模块记录的 `s_conn_handle` 查询（`NONE` 时直接返回 `BLE_HS_ENOTCONN`）。
2. **迟到 STA_START 打断新链路**：探测在 ~150ms 完成，而真正的 STA_START 事件约 +2.3s 才到；它走处理器非 await 分支，无条件重开窗口 → 把刚建立的连接打成 `run -> init`（单轮 6.8s）。新增 `s_wifi_probe_completed_gen`：被探测收尾过的代号，其后续事件只记日志并忽略（`probed=1 / ignored`）。

两条都只在设备上才能暴露，主机测试无法覆盖。

### 1.5 DEF-BLE-001 诊断字段

- `main/bt_gatts_nimble.c`：新增 `s_last_rx_ms`（每次 GATT 写更新，连接/断开/reset 清零）；新增
  - `int app_ble_gatts_conn_find(void)` → `ble_gap_conn_find(BLE_HS_CONN_HANDLE_NONE, &desc)`，`0`=协议栈仍持链路；
  - `int32_t app_ble_gatts_rx_age_ms(void)` → 距最近一次写入的毫秒数，`-1`=本次连接从未写入。
- `main/bt_gatts.c`：Bluedroid 构建返回 `1 / -1`（该 profile 无此诊断）。
- `main/diag.c`：1s 节拍行追加 `cf=<conn_find> rx_age=<ms>`。
- `main/cmd.c`：`device.status.ble` 追加 `conn_find`、`rx_age_ms`。

这组字段用于判别 DEF-BLE-001 的两个假设：`cf=0 且 rx_age 很大` → 链路真实存在但对端僵尸（H1）；`cf≠0 而 connected=1` → 应用层标志悬挂（H2）。**本轮只加诊断，不改断链策略**。
