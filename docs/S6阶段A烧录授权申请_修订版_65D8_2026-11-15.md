## 2. 执行前置门禁（强制，v2：新增镜像 sha 与"新鲜映射证据"）

```
tools/preflight_flash.py \
  --port /dev/ttyUSB1 \
  --log-dir artifacts/cmd04_flash_20261114/phaseA \
  --expect-device-id IotHub-65D8 \
  --expect-build-sha 7e9b8520d \
  --elf build-release/iothub.elf
```
**必须 rc=0**。脚本强制的四项：

| # | 判据 | 说明 |
| --- | --- | --- |
| 1 | 日志中**存在** `rst:0x1`，且其后存在 `client_id=iothub-<WiFiMAC>` | 证明映射属于**当前上电会话**；**无 boot 标记直接拒绝**（`rfind` 返回 -1 的边界已封） |
| 2 | **两份日志对应的 capture 进程仍存活且持有该串口**（PID 文件 + `/proc/<pid>/fd` → `/dev/ttyUSBx`，且 cmdline 含 `capture_serial <port>`） | **主证据**："当前会话正在采集" |
| 2b | 两份日志 `mtime` 均在 `--max-age-sec` 内 | **辅助**新鲜度条件；不单独证明录制在运行（mtime 可能来自停止前的最后写入） |
| 3 | 目标端口 device_id == `IotHub-65D8` | `device_id = WiFi MAC 末 4 位`；BLE 地址 = WiFi MAC + 2 |
| 4 | **另一端口**亦有 boot 后有效 client_id，且**与目标设备不同** | 防止两端口指向同一设备/另一端口无身份 |
| 5 | ELF `build_sha` == `7e9b8520d` | 镜像身份强制校验 |

其他强制项：
- 烧录前停止 ttyUSB1 录制并记录 gap；烧录后立即恢复录制；
- 烧录后立即 BLE 反证：`device.info.build_sha == 7e9b8520d`，不符 → STOP；
- **C8E4 未触碰证据的采集口径（评审要求）**：**不主动连接 C8E4、不复位、不下发命令**；
  其基线仅从 ttyUSB0 的**既有连续采集**中被动取证（`client_id`/`build_sha` 相关日志行
  + 日志连续性）。烧录前已存的一次 BLE 基线（`d4188551c` / 22904232ms @ 07:55:47，
  `baseline_before_flash.json`）作为历史参照，后续不再新增主动连接证据。
