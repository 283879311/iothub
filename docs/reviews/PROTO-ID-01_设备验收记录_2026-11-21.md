## 3. BLE 验收（B0–B15）

### 3.1 结果摘要

- 报告结果：**20 PASS / 0 FAIL**。
- `B15-seq`：**SKIP**。BLE 单次 RTT 约 0.5–1.1 s，超过 200 ms 限频窗口，顺序法无法判定“无效 ID 不占配额”。
- 背靠背 B15：**PASS**。两帧间隔 50 ms，不等待首帧响应；报告结果为第一帧 `invalid_argument`、第二帧 `ok`。

### 3.2 B15 正式方法（本次采用）

1. 连续发送两帧请求，帧间隔 50 ms。
2. 发送第二帧时不等待第一帧响应。
3. 第一帧使用无效 ID，预期 `invalid_argument` 且响应不含 `id` 字段。
4. 第二帧使用合法 ID，预期 `ok`，不得返回 `rate_limited`。
5. 分别保存两帧原始请求、响应和时间戳，并记录实际发送间隔。

本次报告结果：`r1=invalid_argument`、`r2=ok`，判定 **PASS**。

### 3.3 B15-seq 的 SKIP 口径

顺序法需要在限频窗口内完成无效请求响应及后续合法请求；本次 BLE 单次 RTT 约 0.5–1.1 s，超过 200 ms 窗口，故记为 `SKIP(BLE RTT 超过限频窗口，顺序法不可判定)`，不计入通过率。**MQTT 的 RTT 门槛不套用到 BLE 背靠背方法。**

### 4.1 结果摘要

### 4.2 MQTT RTT 判据（冻结口径）

- 无效请求 RTT **<150 ms**：具备 PASS 资格。
- 150–200 ms：`SKIP(RTT 不达标)`，最多重试 3 次。
- ≥200 ms：直接 SKIP。
- 每次 SKIP 必须记录实测 RTT，且不计入通过率。

本次 M12：`rtt1=108 ms`，满足 PASS 资格，执行报告判定 PASS。

### 4.3 M8 FAIL：number ID 大数回显漂移

| 项目 | 值 |
|---|---|
| 用例 | M8 |
| 复现固件 | `1.3-57612ba` |
| build_sha | `a4afb2b29` |
| 请求 ID 字面量 | `9007199254740993`（2^53+1） |
| 预期回显 | `9007199254740992` |
| 实测回显 | `9007199254740990.0` |
| 结论 | **FAIL** |

**预期值按 IEEE-754 double 语义，不是原始字面量。** 十进制整数 `9007199254740993` 转换为 binary64 double 时，得到的值是 `9007199254740992`；回显应保留该 double 的数值语义。

执行方报告的根因定位为 cJSON 1.7.19 数值打印路径：先以 `%1.15g` 格式化，再用相对误差比较决定是否回退到 `%1.17g`。对该值，15g 字符串重解析为 `9007199254740990`，绝对误差为 2；比较容差 `max(|a|,|b|) * DBL_EPSILON` 也恰为 2。因比较条件使用 `<=`，错误回读值被接受，17g 兜底没有触发。

该根因复现与代码路径分析是执行方提供的报告；评审方尚未在目标构建环境独立复现。该问题位于 cJSON 数值打印行为与 ID 响应适配的交界处，修复授权限定在 `app_cmd_v1_id_add()` 的 NUMBER 分支，不修改 cJSON 本体。
