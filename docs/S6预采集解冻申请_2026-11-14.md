## 1. 双 TTL 时间线（v8 口径不变）

```
trial deadline     = esp_timer_get_time()/1000 + 300000   （store_trial 时刻起）
operation deadline = app_operation_now_ms()   + 300000   （set_state(GOT_IP) 时刻起）
Δ = T1 − T0 实际毫秒间隔（连接/netcheck 在 T0 之前，不计入）
trial deadline 不晚于 operation deadline；Δ>0ms 严格先到期，Δ=0ms 同时到期
T0/T1 无设备侧精确时间戳——主机 monotonic 区间取证，Δ 以测量区间报告
```

## 2. 分支与顺序（token 逐命令检查 + probe 判断前移）

```
S0 无条件 auth.login（本轮 token 计时起点）→ 六维身份守卫 → 串口在录确认
   → 前置 device.status/config.get（固化当次实测 DHCP 地址+身份+时刻）
S1 分支① BLE sync trial cancel（零 op 零 async）：
   sync tryconnect → 受理响应 → trial ready 采集
   → not_found 负向对照：operation.get{op-00000000CDEF1234} + 同刻 network.status
   → BLE cancel{trial_id} → cancelled 采集 → trial idle
S2 分支② BLE sync 04c 段 A（独立）：
   sync tryconnect → 原始受理响应帧+键序 → trial ready 采集
   → BLE cancel → trial idle
S3 分支④ BLE sync 专用 TTL（无 operation）：
   sync tryconnect → trial ready（T0' 主机时钟）→ 不 cancel、保持 BLE 会话
   → T0'+270s 起每 15s 预到期采样（应仍 ready）
   → T0'+300s 起每 15s 查询至 idle（lazy clear 成对证据）
S4 分支⑤ MQTT async expired（唯一改指向段）：
   （受保护命令发送前逐条检查 token 年龄——见 §3 续签规则）
   → 改指向（§5）→ 接入 mini_broker ≤75s
   → async tryconnect(CMCC-502+口令) → GOT_IP（主机时钟区间记录两转换）
   → S5d 机会性轮询（GOT_IP→EXPIRED 窗口内）：operation.get + network.status；
     "GOT_IP 且 trial idle" → 归档"清理原因未判定"
   → op-E 自然 EXPIRED → cleanup 确认（persistent 恢复）+ trial 终值记录
   → **probe 存在性判定（在发起 op-V 之前完成）**：BLE network.scan 完整性
     五条件——status=="ok"、BLE 响应全部分片完整接收、count==aps.length、
     **aps 存在且确为数组**、完整 aps 中不存在 __jobclear_probe__；
     任一不满足 → 重扫一次 → **重扫后仍不满足 → 走降级路径**（放弃 op-V，
     该项记"证据降级/未完成"，不得以完整 job-clear 已验证结论收尾）；
     两轮扫描 probe 均存在 → 同走降级路径
   → 降级未触发：async tryconnect(__jobclear_probe__)，不携带 idempotency_key
     → 受理返回 operation_id 必须 ≠ op-E id（新 id = op-E job 已清确证；
       返回 op-E id = job 未清 → STOP）
     → op-V 经 run 内 app_cmd_net_async_clear_job_sync() + 直接置
       FAILED/AP_NOT_FOUND 清除自身 job/cfg——不经 cleanup_fn
   → **auth.login 续签③（op-V 结束后、恢复 config.set 紧邻之前）**
   → 恢复指向 → mqtt_connected=true（≤80s 超限 STOP）+ config.get 回读
S5 trial mismatch 分支：标"不可达/未覆盖"（不计入验收覆盖）
S6 结束态验收（§7）→ SHA256SUMS
```

**§2.1 token 续签规则（逐命令）**：每次发送受 token 保护的 BLE 命令前，检查
**当前 token 年龄——年龄从最近一次成功 `auth.login` 签发时刻计算**（不是固定
自 S0；续签后起点随之重置）；**达到 480s → 先 `auth.login`；该续签的成功条件
为三件事同时完成：`auth.login` 成功、harness token 更新、计时起点重置**——
三者作为同一成功条件，任一失败（含 token 更新失败）立即 STOP；成功后发送
原命令。该规则覆盖 S3 的 270s 采样与 idle 查询、S4 的 GOT_IP→EXPIRED 轮询
与 op-V——不存在阶段入口检查遗漏的长等待窗口；逐命令续签 ≈0.5s/次，且年龄
起点随续签重置后不会出现"每条命令都重登"的限频风险。

## 6. 异常恢复规则（v8 + 重试措辞对齐）

身份漂移/新 boot → STOP（改指向状态先恢复）；BLE 断连 → 重连 ≤3 次 → 失败
按 §5 处置（分支④ 断连清 trial，作废重试至多一次）；cancel 无响应 → 重试
一次 → STOP；GOT_IP 90s 超时 → 重试至多一次；cleanup 后 120s 未恢复 → STOP；
auth.login 失败 → STOP；**扫描完整性五条件任一不满足 → 重扫一次 → 重扫后
仍不满足 → 降级路径；probe 两轮均存在 → 降级路径**；op-V 受理返回 op-E id →
STOP；恢复轮询 80s 超限 → STOP；未列明异常一律 STOP + 恢复 + 归档，不即兴处置。

## 7. 结束态验收（重试措辞对齐）

| 级别 | 判据 |
| --- | --- |
| 正常验收 | 恢复采集前运行态（CMCC-502 / TB:21883 / trial idle / 无活动 op）——"无活动 op 以 op-V 受理新 id 确证"以**扫描完整性五条件满足**为前提 |
