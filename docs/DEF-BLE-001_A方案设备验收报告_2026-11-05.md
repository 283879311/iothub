## 1. R-BLE-1：先写后杀（PASS）

```
[1/1] ok (3.1s, killed)
W (109545) bt_gatts: idle terminate conn=0 idle=90s (no subscribe, no app activity)
W (109595) bt_gatts: central disconnected (reason=0x216)
→ 扫描恢复：IotHubBLE-C8E4
```

- 空闲判据准点（90s，1s 节拍内）；
- 本地 DISCONNECT 事件 reason=`0x216`（HCI 0x16 local host terminated）——这是我们发起 terminate 后控制器回报的本地原因，与传入的 `BLE_ERR_REM_USER_CONN_TERM(0x13)` 不是同一个字段，属正常语义；
- 断开后走既有路径，广播自动恢复（扫描可见）。

## 2. R-BLE-2：连上立即杀（PASS，连接年龄兜底专项）

```
[1/1] ok (1.1s, killed)      ← 未写任何帧，rx_age 语义为 -1
W (229565) bt_gatts: idle terminate conn=0 idle=90s
→ 扫描恢复
```

评审指出的 `rx_age=-1` 漏洞已由 `max(s_last_rx_ms, s_conn_since_ms)` 兜底修复：无写入的连接同样 90s 准点回收。

## 3. R-BLE-3：订阅后静默（PASS，不误杀）

```
[child] idle-sub: holding 120.0s without writes
[1/1] ok (124.1s)            ← 120s 内链路保持，子进程正常断开
idle terminate 计数：before=2 → after=2（无新增）
```

订阅中的会话被硬条件 `!s_data_subscribed && !s_cmd_subscribed` 保护，120s 静默不触发回收。
