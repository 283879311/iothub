## 1. 双 TTL 时间线（本轮唯一需特别注意的证据口径）

async 路径实际顺序（dc254d5 源码口径，评审已核实）：

```
T0 = app_cmd_net_store_trial()          → trial TTL 起（300s，trial 先计时）
T1 = app_operation_set_state(GOT_IP)    → operation TTL 起（300s，后计时，T1 = T0+Δ）
    Δ = 连接+MQTT 回连+netcheck 时长（预计 10–40s，不预设精确值）
trial 预计到期：T0+300s；operation 预计到期：T1+300s（恒晚于 trial）
operation 过期时 cleanup 会按 operation ID 匹配清理关联 trial
```

**两个独立观测点（不合并、不互推因果）**：

| 观测点 | 时点 | 动作 | 归档口径 |
| --- | --- | --- | --- |
| A · trial TTL | ≈T0+300s（每 30s 轮询，最早证据优先） | `network.status` 记录 trial 块状态；operation 仍 GOT_IP | 若 trial 在 operation 终态**前** idle ⇒ trial 自身 TTL 清理得证；**否则**按实际 cleanup 路径归档，不推断原因 |
| B · operation TTL | ≈T1+300s | `operation.get`（expired）+ cleanup/job clear 确认 + trial 终值记录 | expired/cleanup/按时序归档 |

## 2. 分支与顺序（评审 §3 裁决顺序）

```
S0 身份守卫（§3 六维基准）→ 串口在录确认 → 前置 device.status/config.get
S1 分支① BLE sync trial cancel（零 op、零 async job）：
   BLE sync tryconnect(CMCC-502+口令) → 受理响应（got_ip 形态）
   → network.status（trial ready）→ BLE network.cancel{trial_id}
   → 采集 {trial_id, state:"cancelled"} → network.status（trial idle）
S2 分支② BLE sync 04c 段 A（与①独立，不复用 trial）：
   BLE sync tryconnect → 原始受理响应帧 + 键序存档
   → network.status（trial ready）→ BLE cancel → trial idle
S3 分支③ trial 不匹配：只读组合构造尝试；不可构造则记录原因，不强造
S4 分支④ MQTT async expired（唯一改指向段）：
   S4a 改指向（§5）→ 等接入 mini_broker ≤75s
   S4b MQTT async tryconnect(CMCC-502+口令) → GOT_IP（记 T0/T1 实测值）
   S4c 观测点 A（trial TTL）→ 观测点 B（operation TTL 自然 expired）
       → cleanup 确认（persistent 恢复）+ job clear 确认（≥120s）
   S4d 恢复指向 → TB:21883 connected 验证
S5 结束态验收（§7）→ SHA256SUMS
```

衔接已核实：①②均以 cancel 收尾（trial 清）→ 后续 sync/async 入口的
trial-busy 检查不阻塞；④ op 过期时点与 trial TTL 近同步，双观测点分别取证。

## 4. 槽位与操作台账

| op | 分支 | 终态方式 | 保留 | 释放条件 |
| --- | --- | --- | --- | --- |
| 仅 1 个 | ④ async expired | **自然 expired**（真实生命周期） | 终态起 600s | cleanup 完成 + job clear 确证（≥120s） |

## 5. MQTT 临时改指向台账（唯一例外，最后执行）

| 项 | 值 |
| --- | --- |
| 原值 / 临时值 | `139.9.93.245:21883` / `192.168.1.19:21883`（PC mini_broker） |

| 暴露窗口 | 仅分支④（≈8–10 分钟）；S1–S3 全程原配置 |

## 6. 异常恢复规则（与 v3 相同，要点重列）

身份漂移/新 boot → STOP（改指向状态先恢复）；BLE 断连 → 自动重连 ≤3 次 →
失败按 §5 声明处置；cancel 无响应 → 350ms 重试一次 → 仍无响应 STOP；
GOT_IP 90s 超时 → 采集实态、重试至多一次；cleanup 后 120s 未恢复 → STOP；
未列明异常一律 STOP + 恢复入口 + 归档上报，不即兴处置。

## 7. 结束态验收（v3 收紧口径不变）

正常验收 = 恢复采集前运行态（CMCC-502 / TB:21883 / trial idle / 无活动 op）；
cleanup 后落在 TQ2026 → 单列"已知回落路径"，不判完全恢复、须解释差异；
禁止为满足结束态修改生产 profile。

## 8. 冻结边界不变

不含：烧录、整机重启、NVS 直接写入、config.set 持久键（唯一例外=§5 且恢复）、
apply（成功路径到 got_ip/trial ready 即止）、任何绕过真实 cleanup 的人为终态、
与其他验收并发。
