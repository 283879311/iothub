## 1. 更正上一轮结论

上一轮报告称“租户内无 `IotHub-65D8` 设备”，该结论**错误**，现予更正：

- `GET /api/tenant/devices?deviceName=Test%20Device%20C1` 返回 `200` 但 `data=[]`；按分页列表 `GET /api/tenant/devices?pageSize=100&page=0` 可找到 `Test Device C1`。
- 原因：`deviceName` 精确查询未命中（服务端匹配语义未确认），不能据此判断设备不存在。
- 设备名 `Test Device C1` 与固件上报的 `device_id=IotHub-65D8` 不是同一字段；用户已确认二者对应，`fw_version` 属性 `1.3-956afcd` 与 Stage B 身份一致，构成佐证，但因 attributes 无 `device_id`/`build_sha`，**不是独立身份证明**。

4. 无论上述机制如何，现存 4 字段时间戳陈旧是事实；仅凭 attributes **无法证明**某个样本产生于测试窗口内。

## 4. 对 C15-2 判据的影响

| 维度 | 结论 |
|---|---|
| 观察者副作用 | REST GET 不建立 MQTT 会话，Stage-B 的“同 token 第二连接驱逐设备会话”副作用**不再存在** |
| 字段来源 | 设计文档的字段来源表得到验证：4 个目标字段在 attributes；`sta_has_ip` 只在 telemetry |
| 身份门禁 | attributes 无 `device_id`/`build_sha`，身份仍须由 BLE `device.get` 提供（现有 harness 已具备） |
| 窗口判据 | 严格“样本 ts ∈ 窗口”判据对未变化字段不可满足；直接套用会再次得到 `NOT_COVERED` |
| 权限 | `TENANT_ADMIN` 非只读，C 的只读前置不成立 |

因此 C 的形态需要重新定义，不能按原设计直接实现。

## 5. 可选路径（均需单独授权）

| 路径 | 内容 | 代价/风险 |
|---|---|---|
| A. 弱化语义 | 以“读取时刻 T ∈ 窗口”为观察时刻，记录 `lastUpdateTs` 并标注新鲜度；`sta_ip` 交叉核对改用窗口后新鲜 BLE `network.status`；身份仍用 BLE | 不改固件；但 attributes 证据降级为“最后上报值”，不能证明窗口内重发 |
| B. 混合 REST 观察 | 追加 REST telemetry timeseries 只读查询（`net_mode`/`uart_baudrate`/`sta_has_ip` 有逐周期时间戳），attributes 仅取 `sta_ssid`/`sta_ip` 最后值 | 需新增授权（telemetry 不在本轮 “attributes 只读” 范围内）；判据需再次修订 |
| C. 真正只读账号 | 提供 `CUSTOMER_USER` 或只读角色账号（可核验权限范围） | 需 TB 侧创建账号（写操作，当前未授权） |

本轮未读取 telemetry timeseries，避免超出“attributes 只读查询”的授权范围。
