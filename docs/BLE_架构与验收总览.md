# BLE 架构与验收总览

> **状态：ACTIVE（BLE 专题唯一导航与状态总览）**  
> 更新：2026-11-16。本文整合原《BLE需求基线》《功能现状与目标》《设备侧要求检查表》的有效结论；wire 命令定义仍以 [BLE 命令协议规范](BLE命令协议规范.md) 和仓库 `contract/v1/` 为准。

## 1. 当前产品架构

- **角色与协议**：NimBLE Peripheral；NUS Service UUID `6E400001...`，CMD RX/TX 为 `6E400004/005`，DATA RX/TX 为 `6E400002/003`。
- **命令面**：仅 v1 envelope（`version=1.0`、`cmd/args`）；v0 `method/params` 已从固件入口删除，不能作为兼容接口。
- **认证**：BLE 登录后使用会话 token；当前链路未配对/未加密（SM_LVL=0），应用层 token 不等于链路安全。敏感凭据不得进入日志、状态或错误消息。
- **职责**：BLE 是本地设备管理与救援通道；Wi-Fi/MQTT 离线时仍应可连接并诊断/修复网络。MQTT 承担云端遥测、状态同步和受限 RPC，不取代本地 BLE 配置通道。
- **数据面**：DATA 经 `data_pipe` 路由；它是 best-effort 字节管道，不具备应用层 ACK、序号、重传、帧重组或背压保证。GATT 写成功不等于端到端送达。
- **旧能力**：Web/HTTP 配置、SoftAP、Classic Bluetooth/SPP 已不属于当前产品架构；不得从旧验收材料推断它们仍可用。

## 3. T3 / T4 / T5 的关系与结论

| 阶段 | 验证对象 | 当前可确认结论 | 不可外推的部分 |
|---|---|---|---|
| T3 | GATT、CMD/DATA 基础功能与 MTU 分片 | 历史设备记录 15/15 功能项 PASS | DATA 可靠传输未签收；UART1 入站路径曾存在缺口，不能把 T3 功能 PASS 扩大成全链路可靠 |
| T4 | 微信小程序真实 Android/iOS 兼容与交互 | 交互协议/测试矩阵已形成；历史失败分析定位过扫描/连接问题 | Android 真机完整验收表仍待实际回填；iOS 曾因无设备 BLOCKED；T4 整体不得标 PASS |
| T5 | 多轮网络操作、断连、异常与资源稳定性 | 6h soak 报告有七项 PASS；T5 V1 软件复位票据报告 PASS（仅 esp_restart 路径） | 6h soak 不等于完整 T5；V1 不证明 EN 硬复位/掉电；T5 V2 r2.2 为计划，G2 待复审、G3 设备操作未授权 |

## 4. 当前安全与可靠性限制

1. BLE 链路当前未加密/未配对；token 仅提供应用层认证。链路安全是独立风险，不得描述为已解决。
2. DATA 通道没有 ACK/重传/背压，不承诺可靠交付。
3. Notify 可能丢失；客户端必须用 `operation.get` 补查状态，不能把通知当作唯一真相。
4. T3/T4/T5 旧证据绑定旧设备、旧固件与旧测试环境；新回归必须记录设备身份、固件完整 SHA、工具/客户端版本和原始日志。
5. 设备操作、复位、烧录、串口采集均须遵循独立授权；本总览不构成操作授权。

## 8. 当前安全边界

- 当前 BLE 链路未配对/未加密；应用层 token 不能替代链路加密和设备身份认证。
- NVS 中的 Wi-Fi/MQTT 等配置凭据仍有明文存储风险；首启强制改密/NVS 加密目前按既有产品决策不排期，部署时必须人工修改默认凭据并限制设备物理访问。
- 安全风险不因 Web/HTTP/SPP 旧功能移除而自动关闭；任何重新排期应独立评审资源成本和安全方案。


### 7.1 特征值瘦身与当前手机回包契约

旧 1.3-46 的特征值值模板 1B / max_length 显式声明属于当前 NimBLE GATT 实现细节；是否完成手机兼容验收以 T4/四特征执行记录为准。旧推进表对 login 回包层级存在前后版本描述，当前客户端必须严格按 `contract/v1/` 与 `docs/BLE命令协议规范.md` 核验，不能把历史 `result.token` 或 `result.result.token` 描述当成当前契约。

### 7.2 可选体验项（不作为当前阻断）

- Central 目标设备筛选/名称前缀只服务兼容代码与测试工具；当前产品启动角色固定 Peripheral，不作为产品功能缺陷。
- 连接态持续可扫描、Unknown Characteristic 显示属于可选客户端体验，不进入当前 1.3 验收阻断项，除非产品需求重新确认。
