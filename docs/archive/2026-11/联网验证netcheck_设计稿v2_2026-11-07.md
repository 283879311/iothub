> 4 个修订点已全部合入本稿（标记【P1-1】【P1-2】【P2-3】【P2-4】，P3 两条记入 §8）。

## 1. 目标（用户口径，2026-11-06）

1. **Wi-Fi 自动轮询**：设备找到一个能关联的 Wi-Fi 后，还必须确认它具备互联网访问能力，并且能连接 MQTT，不能仅凭 STA_CONNECTED 或 GOT_IP 就认定网络可用。
2. **MQTT 命令切换 Wi-Fi**：远程下发新的 SSID 和密码后，必须进行事务式切换。只有新 Wi-Fi 和 MQTT 都验证成功，才正式保存新配置；否则回退原配置。

既有设计约束（两份评审已写死，本稿遵守）：
- 探测可取消、有时限、低资源；不得阻塞 operation worker / BLE 事件循环
  （`网络配置切换方案评审备忘_2026-11-03.md` §2.3）；
- **MQTT CONNECTED 不能当互联网证据**；`internet_unverified` 与 `mqtt_unavailable`
  必须分开；`operation.get` 补 `stages` 而不是第二套错误码
  （`MQTT网络配置控制方案评审回复_2026-11-03.md` §5）。

已确认口径：两条一起做；探测**只探 broker host:port**；不加 VERIFYING 状态，用 `stages` 表达。

## 2. 模块

### 2.1 `main/netcheck_policy.c` —— 纯判定（主机单测）

`facts(mqtt_configured, dns_pending, dns_ok, tcp_done, tcp_ok, mqtt_connected, mqtt_fatal) → verdict`：

| 事实 | 判决 | 阶段名 |
| --- | --- | --- |
| MQTT 未配置（host 空或 port 0） | OK | `skipped`（不伪装成已验证） |
| DNS 仍在解析 | CONTINUE | — |
| DNS 失败 | FAIL_INTERNET | `internet` |
| TCP 未出结果 | CONTINUE | — |
| TCP 失败 | FAIL_INTERNET | `internet` |
| TCP 通，MQTT 未连、非致命 | CONTINUE | — |
| TCP 通，MQTT 致命（认证被拒） | FAIL_MQTT | `mqtt` |
| 全通 | OK | `mqtt` |

判定只看事实不看时钟；"没验完"永不等于"通过"。

### 2.2 `main/netcheck.c` —— 探测任务

- 一次性任务 `netcheck`（4096B / prio 4），完成自删；**收尾与 start() 竞态**
  由任务退出路径复核 `state==RUNNING` 接续新代次，不会出现"新代次无人跑"。
- 【P1-1】**时序预算**：总预算 **25s** = DNS ≤3s + TCP ≤2×2.5s + MQTT 等待占其余。
  - DNS 用 lwip **异步** `dns_gethostbyname`（IP 字面量同步返回），轮询等待可取消
    —— 评审指出 `getaddrinfo` 是阻塞 DNS，取消/预算都管不住它；
  - 取消收敛 ≤3s（最长的有界步 = 单次 TCP select 2.5s）；
  - `app_netcheck_wait` 调用方超时传 25s；**accepted_ttl=45s** 覆盖 15s 连接 + 25s 验证。
- 【P2-3】MQTT 阶段**入口主动 `app_mqtt_schedule_restart()`**：原设计被动等
  2/5/10/20/30s 退避，走到 20/30s 档时 15s 窗口内 MQTT 根本没机会发起，
  好网会被误判 FAIL_MQTT 而错误回滚。operation 活动期该请求被 defer 合并、
  由 defer 放行（≤15s）执行，仍在验证预算内；无 operation（自动轮询路径）时立即执行。
- 代次绑定：结果绑定 `wifi_runtime_t.link_gen`；断链/重新拿到 IP 换代，
  旧代次结论一律不作数。在跑旧代次时新 start() 记 pending，收尾自动接续。
- 收尾日志含 `stack high watermark`（评审 P3-2：设备验证时核对）。
- IPv4 only：解析出 AAAA 按"不可达"处理（本固件无 IPv6；记录在案）。

## 3. 自动轮询接入（R1）

- `wifi_runtime_t` 新增 `link_gen` / `net_verified` / `net_verify_stage[8]`（runtime lock 保护）；
  GOT_IP 与 STA_DISCONNECTED 各使 `link_gen` +1 并清 `net_verified`。
- **GOT_IP 主路径不再清 mask / 退避归零**——"成功奖励"整体迁到验证通过回调
  （`app_wifi_netcheck_on_result`，netcheck 任务上下文）：
  - OK → 清 `attempted_mask`、运行时退避归零、`net_verified=true`；
  - **FAIL_INTERNET** → 标记当前 profile（mask 置位）、`sta_retries=RETRY_LIMIT`
    （跳过 3 次直连重试）、`esp_wifi_disconnect()` → 既有断连链换 profile /
    5-10-30-60 退避，永不 settle；
  - **FAIL_MQTT → 只记录不拆链**（设计裁定，评审未否决）：broker 问题换 AP 无解，
    MQTT 自身退避在跑，拆链只会造成无意义震荡；`net_verified` 保持 false，
    `network.status` 可见。**此不对称是本稿明示的设计决策，设备验收时一并确认。**
- 试用（tryconnect）路径：`app_wifi_tryconnect_on_got_ip` 匹配成功处**补写运行态真值**
  （`sta_connected/sta_has_ip/sta_ip/connected_ssid`，此时确实持有 IP）——
  不写则 `app_mqtt_apply_config` 因 `!sta_has_ip` 拒启，MQTT 阶段无从谈起；
  随后换代 + 启动 netcheck。写点在 tryconnect 状态锁**外**（该锁从不嵌套
  runtime/profiles 锁）、事件位置位**前**（worker 看到 OK 即开始 teardown）。
- 启动失败（如内存）不判通过：链路按未验证保留，退避/monitor 兜底。

## 4. 事务换网接入（R2）

- worker（`app_cmd_net_async_run`）：`try_connect_ip` OK → `store_trial` →
  **等 netcheck 判决**（`app_netcheck_wait(gen, 25000)`）→ 通过才 `GOT_IP`；
  失败 → 【P2-4】**二次 R5 复核（gen+state）后**才走 `app_cmd_net_async_cleanup`
  （判别点 B：清 trial/job + `rescue=restore_persistent`）→ `FAILED(internet_unverified | mqtt_unavailable)`。
- 【P1-2】**accepted_ttl 两处同步改 45s**：`app_cmd_take_accepted_ttl()` 默认
  （cmd.c:103，FI 构建）与非 FI 硬编码（cmd.c:586）——FI 是 mqtt_net_txn=on 的
  v1-only BIN 变体，两处不一致会造成行为分叉。op_ttl 旋钮 clamp [500,60000] 仍覆盖。
- `network.apply` 提交前兜底：`app_netcheck_ok_for_gen(当前代次)` 不成立 →
  按阶段拒绝 `internet_unverified` / `mqtt_unavailable`（防 300s GOT_IP 窗口内
  链路已变化；SUCCESS 幂等返回不受此门影响）。
- `app_cmd_net_async_cleanup` 入口补 `app_netcheck_cancel()`。

## 8. 已知限制与 P3 记录

1. 【P3】试用期运行态真值：trial 存续期间 `network.status` 显示"已连候选 AP"
   （`connected_ssid`=候选），**预期行为**；trial 结束后由既有路径覆盖。
2. 【P3】netcheck 任务 4096B 栈：收尾日志打印 high watermark，设备验证时核对。
3. 无 MQTT 配置时不验证（`skipped`）——明确记录，不伪装成已验证。
4. 只探 broker：broker 在局域网时"互联网"退化为"broker 可达"（用户已确认口径）。
5. BLE 连着时不扫描：FAIL_INTERNET 后换 profile 要等 BLE 断开（现有策略，不改）。
6. `app_mqtt_stop` 在 WiFi 事件处理器内同步最坏 4s+12s（`mqtt.c`），拖慢换网时序
   ——本轮只记录不修。
7. MQTT 未配置或 host 为 IPv6-only 域名时按 §2.2 口径处理；静态锁定设备
   FAIL_INTERNET 后只重试正式 SSID（不能换网，设计如此）。
8. FAIL_MQTT 不拆链的不对称（§3）：若验收认为应拆链重试，改为与 internet 同路径
   即可（一处 strcmp）。
