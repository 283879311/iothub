# BLE 当前状态与维护边界

> **状态：ACTIVE**  
> 本文只维护固件 1.3 当前 BLE 架构、未完成事项和必要证据。命令字段、参数与错误码以 `contract/v1/` 和 [BLE 命令协议规范](BLE命令协议规范.md) 为准。

## 1. 当前状态

- **角色**：产品启动固定为 NimBLE Peripheral；NUS CMD RX/TX 为 `6E400004/005`，DATA RX/TX 为 `6E400002/003`。
- **命令协议**：仅接受 v1 envelope（`version=1.0`、`cmd/args`）；v0 `method/params` 不是兼容入口。
- **认证**：BLE 登录后使用短时会话 token。当前链路未配对、未加密（SM_LVL=0）；应用层 token 不提供链路加密或设备身份认证。
- **职责**：BLE 是本地管理与网络救援通道；不依赖 Wi-Fi/MQTT 在线。云端遥测、状态同步和受限 RPC 由 ThingsBoard MQTT 承担。
- **数据通道**：DATA 经 `data_pipe` 路由，属于 best-effort 字节管道；没有应用层 ACK、序号、重传、帧重组或端到端背压保证。GATT 写成功不等于业务数据已送达。
- **移除能力**：Web/HTTP 配置、SoftAP、Classic Bluetooth/SPP 不属于当前产品架构，不应作为固件 1.3 待启用功能。

## 2. 未完成事项与限制

| 项目 | 当前结论 | 后续边界 |
|---|---|---|
| 手机端四特征完整验收 | 固件侧 v1 命令入口和回包路径已实现；手机端 RX/TX/CMD RX/CMD TX 的完整真机验收仍未闭环 | 重新验收必须记录当前固件完整 SHA、手机/App 版本、设备身份和原始日志；旧轮次结果不能替代 |
| Android/iOS 兼容与 T5 韧性 | 现有资料不足以确认 Android 完整矩阵、iOS 以及全部异常韧性场景已通过 | 按当前客户端版本和明确用例重新执行；软件复位结果不能外推为 EN 硬复位或掉电验收 |
| 广播看门狗故障路径 | 正常断连重广播有历史记录；故障注入、静默超时和退避失败路径未形成当前完整验收 | 需要独立测试计划、当前镜像和设备操作授权 |
| 链路安全 | 当前 BLE 链路未加密/未配对 | 不得将 token 描述为链路安全；如需启用配对/加密，单独评估兼容性和资源成本 |

DATA 无可靠交付保证、Notify 可能丢失，以及链路未加密，属于当前实现限制，不是已经验收关闭的问题。客户端应通过 `operation.get` 补查操作状态，不把 Notify 作为唯一状态来源。

## 4. 维护规则

- 命令字段、参数、来源权限和错误码变更必须同步评审 `contract/v1/` 与对应协议规范；本总览不复制字段清单。
- 本文只更新当前架构、有效限制、未完成事项和必要入口。
- 不把历史设备、历史镜像或历史客户端结果改写为当前 PASS。
- 任何设备连接、命令执行、复位、烧录或串口采集均须遵循单独授权；本文不构成操作授权。
