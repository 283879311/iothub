# G2 网络事务验收记录

> 日期：2026-10-21
> 固件：`feature/shared-config-cmd`，提交 `7690a97`
> 硬件：B 板，`/dev/ttyUSB0`

## 已通过

### 错误 SSID

`network.tryconnect` 返回 `ap_not_found`，正式配置未变。

### 正确 SSID/密码 + IP 条件

首次失败日志：

```text
tryconnect failed: reason=8(ASSOC_LEAVE)
tryconnect ssid='...' result=3 require_ip=1
```

原因：旧 STA 被 `esp_wifi_disconnect()` 拆除后的断开事件迟到，被误算为候选失败。

修复 `7690a97` 后：

```text
wifi: tryconnect: ssid='...' ... scan=1
wifi: tryconnect ssid='...' result=0 require_ip=1
```

`result=0` 表示候选已获得 IP；旧连接随后恢复：

```text
STA_CONNECTED: static ip mode ...
IP_EVENT_STA_GOT_IP: 192.168.1.42 ...
```

### apply 提交

手机执行 `network.apply`，返回：

```json
{"trial_id":"trial-09AD9802","state":"success","saved":true,"applied":true}
```

串口确认：

```text
rx method=network.apply id=13
apply_wifi_config: ssid='TQ2018' ...
apply_wifi_config: net_mode=1 has_ap=0 has_sta=1
STA_CONNECTED ...
IP_EVENT_STA_GOT_IP: 192.168.1.42
```

Wi-Fi 已切换到目标 SSID，BLE 保持连接。

发现两个问题：

1. **提交的 plan 与试连验证不一致**：`tryconnect` 始终按 DHCP 验证，但 `network.apply` 只写 SSID/口令，保留了旧配置的 `sta_use_static=1` 和 `192.168.1.42`。日志因此出现 `static ip mode`。
2. **apply 后 MQTT 未恢复**：旧静态 IP 保留后，MQTT 反复 `select() timeout`（目标 broker 为 IP 直连，非 DNS 问题），说明目标网络下该静态 plan 不可用或路由不通。

修复 `7714b00`：`network.apply` 同步写入 `sta_use_static=false`，保证提交的是试连阶段实际验证过的 DHCP plan。

用新固件重新执行 tryconnect/apply（目标 `CMCC-502`）后已验证：

```text
wifi: tryconnect ssid='CMCC-502' result=0 require_ip=1
wifi: STA_CONNECTED: dhcpc restarted (connected at t=467397ms)
wifi: IP_EVENT_STA_GOT_IP: 192.168.1.42
mqtt: MQTT connected: subscribed RPC + shared attrs
```

`STA_CONNECTED: dhcpc restarted` 表明提交后走的是 DHCP，不再是 `static ip mode`；MQTT 已重新连上，BLE 连接保持。`network.status` 返回 `sta_ssid=CMCC-502`、`mqtt_connected=true`、`trial.state=idle`。

重启持久性已验证：再次硬重启后，设备仍从 NVS 加载 `CMCC-502`，以 DHCP 获得 `192.168.1.42`，并在 BLE 未连接时成功连上新 MQTT broker：

```text
wifi: apply_wifi_config: ssid='CMCC-502' ...
wifi: STA_CONNECTED: dhcpc restarted
mqtt: Starting MQTT: uri=mqtt://139.9.93.245:21883 ...
mqtt: MQTT connected
diag: heap free=15264 largest=14848 t=8s ble_adv=1 ble_conn=0 mqtt=1
```

这次重启同时证明：Wi-Fi/IP/新 broker 的 TCP 路径可用；低堆时出现的 `select() timeout` 不能直接归因为网络不可达。
