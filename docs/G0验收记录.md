## 已通过

### 启动顺序

```text
I (812) iothub: [boot-4] app_bootstrap_load_config
I (822) iothub: [boot-4a] config_apply_init
I (822) iothub: [boot-4b] app_config_force_ble_peripheral
I (822) iothub: [boot-4c] app_bt_release_unused_memory
I (832) app_bt: BT memory release skipped (mode=ble role=1, BLE always-on)
I (832) iothub: [boot-4d] app_bt_apply_config (always-on peripheral)
I (1262) app_bt: BLE advertising started
I (1282) iothub: [boot-7] app_start_wifi
```

结论：

- BLE 在 Wi-Fi 启动前完成初始化并开始广播。
- BT 内存释放路径因 `role=1/mode=ble` 被跳过，没有拆掉 BLE 控制器内存。
- 运行角色为 Peripheral（role=1）。

### 恢复出厂 + 手机连接（用户实测）

- 恢复出厂后 BLE 仍然启动，手机可以扫描并连接设备。
- 说明默认 Peripheral + always-on 路径生效；BLE 不再依赖恢复出厂前的角色配置。
- 本轮未抓取恢复出厂瞬间的串口日志，未验证角色持久化、断连重连和命令交互。
