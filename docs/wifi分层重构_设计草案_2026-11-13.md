## 2. 目标分层与函数映射（按现有符号归类）

### L1 · Wi-Fi Driver Adapter（`wifi_driver.*`）
36 个驱动调用点收敛为适配函数：`drv_connect/drv_disconnect/drv_set_config/
drv_scan_start/drv_scan_stop/drv_stop/drv_start/drv_set_mode/drv_get_config/
drv_sta_get_ap_info`。`connect_begin/end` 许可计数可下沉至此层。
**纯机械抽取，0 行为变化。**

### L2 · Wi-Fi Connection Manager（`wifi_conn.*`）
`connect_profile_index`、`connect_best_saved_profile(_impl)`、
`retry_with_pmf_required`、`select_best_profile_index/find_best_rssi`、
profiles 存取、scan records/选择、`connect_task_fn`、startup window、
`s_wifi_sta_connecting`、event handler 中 STA_CONNECTED/GOT_IP 状态段。

### L3 · Wi-Fi Operation Manager（`wifi_op.*`，与 `wifi_op_owner.*` 对接）
tryconnect 状态机全套（begin/release/on_disconnected/on_connected/on_got_ip/
match/entry_blocked/defer/finish）、`try_connect_common(_ip)`、
claim/release/abort_consume 原语消费端、`apply_cfg`/`schedule_restart`/
`restart_task_fn`/`cleanup_request`/handover、`s_wifi_op_owner` 消费端。

### L4 · Wi-Fi Recovery Manager（`wifi_recovery.*`）
`boot_monitor` 任务（runtime retry / ble fast retry 120s / startup retry /
connect watchdog）、offline gate、`enter_offline`、`recover_quiesce`、
`recover_from_apply_failure`、LKG capture/equals、退避表。

### 横切（留在共享薄层，不进四层）
`event_handler`（分发骨架——逐 case 改调各层函数）、B5 日志助手与限流、
runtime 结构 + 7 把锁、fault-inject 钩子、`wifi.h` 公共 API。
**`wifi_op_owner.*` 保持独立，不合并回任何大文件。**

## 3. 两个硬问题（决定可行性边界）

1. **共享状态与锁纪律**：`s_wifi` runtime 结构被所有层读写，7 把锁的加锁顺序
   是隐性契约。策略：**先物理分文件、共享 `wifi_ctx.h` 内部头**（结构+锁+原语
   原样），不做语义重设计；语义收敛（如锁粒度调整）留到四层稳定后单独评审。
2. **event_handler 骨架**：巨型 switch 是跨层脊柱。策略：原样保留为分发器，
   每个 case 体改为调用目标层函数——分发器不承载逻辑。

不变量：**B5 日志格式逐字保持**（scheduled/refused/task run + op/gen——竞态
证据依赖它）；`R2` 恢复时延语义不变；BLE 连接态抑制与 120s monitor 语义不变。

四层稳定后另立提案。
