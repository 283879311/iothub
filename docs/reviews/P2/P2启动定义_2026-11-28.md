# P2 启动定义：连接参数条目生命周期验证（2026-11-28）

> 文档状态：PENDING（启动定义，待审核）。
> 本文件只定义实验，不修改代码/Contract/设备，不启动 P2 实验、不执行任何设备或主机操作。
> 基线：`main@57147a3`。未来证据包建议：`evidence/p2-connparam-<date>`（独立分支）。
> 候选：A（主机侧 MGMT `LOAD_CONN_PARAM` 生命周期验证）。

## 1. 目标与范围

- 单一命题：验证 `MGMT_OP_LOAD_CONN_PARAM` 写入的 per-peer 连接参数条目，在**不同类型的“适配器重置”**下是否保留或丢失，以及丢失后重新加载能否恢复。
- 不涉及 ESP32 固件修改；不关闭 C15 任何 `NOT_COVERED`；不重测 A0/A1 的 hook 路径。

## 2. 源码事实（决定判据，v7.0）

| 事实 | 依据 |
|---|---|
| `MGMT_OP_LOAD_CONN_PARAM = 0x0035`，载荷 `param_count(2) + N×15B`；`addr_type` 必须为 `1`（`BDADDR_LE_PUBLIC`） | `include/net/bluetooth/mgmt.h:483-488`；`mgmt.c` `load_conn_param` 类型映射 |
| 历史误用常量（`GET_CONNECTIONS`，空载荷）**不得使用**；正确值为 `0x0035`，详见 C15 报告 §3 | 已入 `main` 的 C15-2 报告 §3 |
| 适配器 close（`btmgmt power off/on`、`hciconfig down/up`、bluetoothd 重启）**不清除** per-peer 参数 | `hci_sync.c` `hci_dev_close_sync` 只做 `hci_conn_hash_flush`；`grep hci_conn_params_clear_all hci_sync.c` = 0 |
| per-peer 参数只在适配器**释放**时清空 | `hci_core.c:2765`，位于 `hci_release_dev()`（unregister / 驱动 release） |
| `unpair_device` 对未配对设备无效 | `smp_cancel_and_remove_pairing` 失败即 `NOT_PAIRED`，不删除参数（`mgmt.c:3178-3190`） |
| `remove_device` 拒绝删除 `auto_connect == DISABLED/EXPLICIT` 的条目 | `mgmt.c:7878-7892`（`LOAD_CONN_PARAM` 写入的条目即 DISABLED） |
| `load_conn_param` 的 clear-disabled 语义：`param_count > 1`，或 `param_count == 1` 且目标地址无条目时，清空所有 DISABLED 条目 | `mgmt.c:7981-7982`、`8024-8026` |

## 3. 重置分类（关键定义，避免误判）

| 类型 | 操作 | 是否释放 hdev | 预期结果 |
|---|---|---|---|
| 重置 A（对照） | `btmgmt power off/on`（等价 `hciconfig hci0 down/up`、重启 bluetoothd） | 否 | 条目**保留**，重连仍为 6000 ms |
| 重置 B（清除构造） | 驱动重绑（btusb unbind → bind）或模块重载（必要时主机重启） | 是（`hci_release_dev`） | 条目**丢失**，重连回落默认 420 ms |
| 侧通道（仅作辅助构造） | 对另一地址发送 `param_count=1` 的 `LOAD_CONN_PARAM` | 否 | 触发 clear-disabled，原 DISABLED 条目被清空 |

说明：若把“适配器重置”理解为 `power off/on`，则判据必须写成“预期**保留**”；本文以**重置 B** 作为“条目丢失、回落默认”的判定路径。两种预期都逐条可判定，但不得混用。

## 4. 目标判据（逐条可判定）

| ID | 判据 | 观测点 |
|---|---|---|
| P2-1 | `LOAD_CONN_PARAM(0x0035, type=1, 24/40/0/600)` 返回 `Command Complete cmd=0x0035 status=0` | MGMT socket 回包 hex；脚本退出码 |
| P2-2 | 加载后首次连接该对端，`LE Create Connection` 为 30–50 ms / latency 0 / supervision **6000 ms** | btmon `LE Create Connection` / `Enhanced Connection Complete` 字段 |
| P2-3 | `power off/on` 后重连，仍为 **6000 ms**（条目保留） | 同上；另记 `btmgmt info` 与适配器恢复时间 |
| P2-4 | 驱动重绑/模块重载后重连，回落内核默认 **420 ms**（条目丢失） | 同上；另记 rebind 命令与 hci0 恢复证据 |
| P2-5 | 重置 B 后再次执行 P2-1 并重连，恢复 **6000 ms** | 同 P2-1/P2-2 |

判定口径：P2-1～P2-5 全部满足为 PASS；任一预期不符即 FAIL（记录现场，不重试）。

## 5. 证据结构（沿用 C15 布局）

```text
p2_connparam_<date>/
├── a0/        # 基线：btmgmt info、加载请求/响应、首连 btmon 参数
├── reset_a/   # power off/on 命令与状态、重连参数（预期保留）
├── reset_b/   # 驱动 rebind 或模块重载命令、hci0 恢复、重连参数（预期 420 ms）
├── reload/    # 重载 0x0035 与重连参数（预期 6000 ms）
├── scripts/   # MGMT 脚本副本（常量自检：0x0035 / type=1；错误常量见 C15 报告 §3）
└── README.md  # 判据表、时间线、排除项、脱敏说明
```

三源要求：btmon 抓包 + 设备串口日志 + 脚本 JSON/日志；证据包独立分支，不与代码/文档分支混合。

## 6. 门禁与前置条件

1. 主机与设备身份核验：适配器地址、设备 `IotHub-65D8`、镜像版本与 `build_sha` 记录在案；
2. 脚本常量自检：`MGMT_OP_LOAD_CONN_PARAM=0x0035`、`addr_type=1`；脚本中若出现历史误用常量（见 C15 报告 §3）即拒绝运行；
3. 设备连接参数策略必须为 `satisfied`，否则不进入后续步骤；
4. 重置 B 属 host-level 高风险操作：必须使用已授权的 rebind/模块重载命令，并预先写明恢复命令。

## 7. 停止条件（逐条）

| ID | 条件 | 动作 |
|---|---|---|
| S1 | P2-1 返回非 `Success`（含 status≠0、超时） | 停止，不重试 |
| S2 | P2-2 首连不是 6000 ms，或设备报 `out of policy` | 停止 |
| S3 | 重置 A 后适配器未恢复（`btmgmt info` 失败/hci0 缺失） | 停止，不进入重置 B |
| S4 | 重置 B 的 rebind/模块重载失败，或 hci0 未恢复 | 停止，按恢复预案处理并保留现场 |
| S5 | 重置 B 后重连不是 420 ms（预期不符） | 停止，记录现场，不重试 |
| S6 | P2-5 重载后不是 6000 ms | 停止 |
| S7 | btmon 丢失关键窗口或串口采集不完整 | 标记“需重跑”，不补造证据 |
| S8 | 设备身份/镜像与授权不符 | 停止 |

## 8. 脱敏规则

SSID、STA IP、网关、BSSID、设备 MAC、host BT 地址、MQTT client_id、口令、token 全部占位符化。注意：对端日志中的 `"password": "<redacted>"` 是 harness `sanitize()` 的占位符（10 字符），不是真实口令；证据说明必须写明这一点，避免再次误读。

## 9. 回滚预案

- 设备：本定义不涉及固件烧写或设备配置写入；连接参数条目为内核内存态，随 `hci_release_dev` 消失。
- 主机：重置 B 的 rebind/模块重载若失败，按预先写明的恢复命令处理；适配器无法恢复时停止并报告。
- 文档：评审分支可 `git revert` 或删除，不影响 `main`。
